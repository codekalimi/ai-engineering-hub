How does human-in-the-loop approval work (interrupt and resume)?

In one lineThe graph pauses at a node, saves its state, and returns the pending action to your app. When a person decides, the app resumes the same thread with their answer.

Step by step
  1. Your app invokes the graph with a thread_id.
  2. A node calls interrupt() with the action that needs approval, e.g. an email draft.
  3. The state is saved by the checkpointer, and invoke returns the interrupt payload.
  4. Your UI shows it to a person, who approves, edits or rejects it.
  5. Your app invokes again with Command(resume=decision) and the same thread_id.
  6. The graph loads the saved state and continues; interrupt() returns the person's decision.
Key details
  • It requires a checkpointer, and the wait can last seconds or days.
  • On resume, the node runs again from its start: keep side effects after the interrupt call.

Use it

What you'd write at work

One middleware line pauses the agent before chosen tools run. A person approves, edits or rejects; the same thread_id resumes it.

python
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command

@tool
def send_email(to: str, body: str) -> str:
    """Send an email."""
    return f"sent to {to}: {body}"

agent = create_agent(init_chat_model("anthropic:claude-opus-5-5"), [send_email],
                     middleware=[HumanInTheLoopMiddleware(interrupt_on={"send_email": True})],
                     checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "invoice-42"}}

result = agent.invoke({"messages": [("user", "Email Ravi that the invoice is attached")]}, config)
request = result["__interrupt__"][0].value                      # paused: nothing was sent
print("needs approval:", request["action_requests"][0]["args"])

edited = {"type": "edit", "edited_action": {"name": "send_email",
          "args": {"to": "ravi@example.com", "body": "Hi Ravi, invoice #881 is attached. Thanks!"}}}
result = agent.invoke(Command(resume={"decisions": [edited]}), config)   # same thread_id
print("tool ran:", result["messages"][-2].content.splitlines()[-1])   # the edited call ran
print("agent:", result["messages"][-1].content)

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API.

What it printed
needs approval: {'to': 'ravi@example.com', 'body': 'Hi Ravi, the invoice is attached.'}
tool ran: sent to ravi@example.com: Hi Ravi, invoice #881 is attached. Thanks!
agent: Done - the email was sent with your edits.

Under the hood

What the library does for you, with its real classes

The mechanism the middleware uses: interrupt() inside a node, a checkpointer, and Command(resume=...).

python
from typing import TypedDict
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph
from langgraph.types import Command, interrupt

class State(TypedDict):
    to: str
    draft: str
    sent: bool

def draft(state: State):
    return {"draft": f"Hi {state['to']}, the invoice is attached."}

def approve(state: State):
    decision = interrupt({"action": "send_email", "draft": state["draft"]})   # Step 2: pause here
    print("  resumed with:", decision)                                        # Step 6: the person's answer
    return {"draft": decision.get("edited", state["draft"]), "sent": decision["approved"]}

graph = StateGraph(State)
graph.add_node("draft", draft)
graph.add_node("approve", approve)
graph.add_edge(START, "draft")
graph.add_edge("draft", "approve")
graph.add_edge("approve", END)
app = graph.compile(checkpointer=InMemorySaver())        # Step 3: state saved at the pause

config = {"configurable": {"thread_id": "t-9"}}          # Step 1
out = app.invoke({"to": "Ravi", "draft": "", "sent": False}, config)
print("paused with:", out["__interrupt__"][0].value)
snapshot = app.get_state(config)
print("waiting at node:", snapshot.next)                 # Step 4: your UI shows this to a person

final = app.invoke(Command(resume={"approved": True, "edited": "Hi Ravi, invoice #881 is attached."}), config)  # Step 5
print("final state:", final)

✓ Ran with langgraph 1.2.24.

What it printed
paused with: {'action': 'send_email', 'draft': 'Hi Ravi, the invoice is attached.'}
waiting at node: ('approve',)
  resumed with: {'approved': True, 'edited': 'Hi Ravi, invoice #881 is attached.'}
final state: {'to': 'Ravi', 'draft': 'Hi Ravi, invoice #881 is attached.', 'sent': True}

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# A tiny version of LangGraph's interrupt() and Command(resume=...).
import json

checkpoints = {}                                   # the checkpointer: thread_id -> saved state

class Interrupt(Exception):
    def __init__(self, payload):
        self.payload = payload

def draft_node(state, resume):
    return {"draft": f"Hi {state['to']}, the invoice is attached."}

def approve_node(state, resume):
    # Step 2: interrupt() pauses with the thing that needs approval
    if resume is None:
        raise Interrupt({"action": "send_email", "draft": state["draft"]})
    # Step 6: on resume, the node runs again from its start and interrupt() returns the decision
    return {"approved": resume["approved"], "draft": resume.get("edited", state["draft"])}

def send_node(state, resume):
    return {"sent": state["approved"]}

NODES = [("draft", draft_node), ("approve", approve_node), ("send", send_node)]

def invoke(inp, thread_id, resume=None):
    saved = checkpoints.get(thread_id)
    state, start = (saved["state"], saved["next"]) if saved else (dict(inp), 0)
    for i in range(start, len(NODES)):
        name, fn = NODES[i]
        try:
            update = fn(state, resume)
        except Interrupt as it:
            # Step 3: save the state and the node to re-run, then return the payload
            checkpoints[thread_id] = {"state": state, "next": i}
            print(f"  paused at '{name}', state saved for {thread_id}")
            return {"__interrupt__": it.payload}
        state.update(update)
        print(f"  ran {name}: {update}")
    checkpoints[thread_id] = {"state": state, "next": len(NODES)}
    return state

# Step 1: invoke with a thread_id
print("app got:", json.dumps(invoke({"to": "Ravi"}, "thread-9")))
# Step 4: a person reviews and edits it in your UI - maybe hours later
decision = {"approved": True, "edited": "Hi Ravi, invoice #881 is attached. Thanks!"}
# Step 5: invoke again with the decision and the SAME thread_id
print("final state:", json.dumps(invoke(None, "thread-9", resume=decision)))

✓ Ran with plain Python 3.9+.

What it prints
  ran draft: {'draft': 'Hi Ravi, the invoice is attached.'}
  paused at 'approve', state saved for thread-9
app got: {"__interrupt__": {"action": "send_email", "draft": "Hi Ravi, the invoice is attached."}}
  ran approve: {'approved': True, 'draft': 'Hi Ravi, invoice #881 is attached. Thanks!'}
  ran send: {'sent': True}
final state: {"to": "Ravi", "draft": "Hi Ravi, invoice #881 is attached. Thanks!", "approved": true, "sent": true}
Watch it in a real system
  • LangGraph: after the call that pauses, state = graph.get_state(config); state.next shows the node that will run on resume and state.tasks[0].interrupts holds the payload.
  • The returned value also carries the pause: look for the __interrupt__ key in what invoke returns.
  • Use a persistent checkpointer (SQLite or Postgres), stop your Python process after the interrupt, start it again and resume with Command(resume=...): it still works, which proves nothing was held in memory.
