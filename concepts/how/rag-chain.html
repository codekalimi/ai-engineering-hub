How does a RAG chain pass the question to both the retriever and the prompt?

In one lineA dict at the start of the chain becomes a RunnableParallel: the same question goes to the retriever and to a passthrough at the same time, producing {context, question} for the prompt.

Step by step
  1. The chain starts with a dict: {"context": retriever | format_docs, "question": RunnablePassthrough()}.
  2. LangChain turns the dict into a RunnableParallel, which sends the same input to every value.
  3. The retriever returns Documents, which format_docs joins into one text block; the passthrough returns the question as it is.
  4. The resulting dict fills the prompt's {context} and {question} variables.
  5. The rest is the normal prompt → model → parser sequence.
Key details
  • Forgetting format_docs puts a list of Document objects into the prompt.
  • RunnablePassthrough.assign(...) adds keys while keeping the input, useful for returning sources with the answer.
chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)
Behind the scenes

See it run

A tiny from-scratch version of what really happens. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: plain Python, nothing to install.

python3 · standard library only
# What {"context": retriever | format_docs, "question": RunnablePassthrough()} does underneath.
from concurrent.futures import ThreadPoolExecutor

DOCS = ["LangGraph adds state and loops.", "LCEL composes runnables with pipes.", "Paris is in France."]
def retriever(question):                     # returns documents sharing a word with the question
    q = set(question.lower().strip("?").split())
    return [d for d in DOCS if q & set(d.lower().strip(".").split())]
def format_docs(docs): return "\n".join(f"- {d}" for d in docs)
def passthrough(x): return x                 # RunnablePassthrough: the input, unchanged

def pipe(*fns):
    def run(x):
        for fn in fns:
            x = fn(x)
        return x
    return run

def parallel(branches):
    # Step 2: a dict becomes a RunnableParallel - the SAME input goes to every branch, concurrently
    def run(x):
        with ThreadPoolExecutor() as pool:
            futures = {key: pool.submit(fn, x) for key, fn in branches.items()}
            return {key: f.result() for key, f in futures.items()}
    return run

# Step 1 + 3: the context branch turns the question into text; the passthrough keeps the question
setup = parallel({"context": pipe(retriever, format_docs), "question": passthrough})
# Step 4: the dict fills the prompt's {context} and {question}
def prompt(d): return f"Use only this context:\n{d['context']}\n\nQuestion: {d['question']}"
# Step 5: then the usual model -> parser (stubbed)
def model(p): return f"(answer written from {p.count('- ')} context line)"

def show(label):
    def run(x):
        print(f"---- {label} ----\n{x}")
        return x
    return run

chain = pipe(setup, show("after the dict step"), prompt, show("prompt"), model)
print("answer:", chain("What does LCEL compose?"))
