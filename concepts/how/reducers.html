How do reducers merge state updates in LangGraph?

In one lineEach state key can have a reducer that decides how a node's update combines with the current value. Without one, the new value overwrites the old.

Step by step
  1. The state schema can annotate a key with a reducer, e.g. messages: Annotated[list, add_messages].
  2. When a node returns an update, LangGraph calls the reducer with the current value and the update.
  3. add_messages appends new messages; a message with an existing id replaces that message instead.
  4. Keys without a reducer simply take the new value.
Key details
  • Reducers matter most when parallel nodes update the same key in one step.
  • Return only changed keys from a node; returning the whole messages list again can duplicate messages.

Use it

What you'd write at work

Annotate state keys with a reducer and parallel nodes can safely write to the same key.

python
import operator
from typing import Annotated, TypedDict
from langgraph.graph import END, START, StateGraph

class State(TypedDict):
    query: str
    results: Annotated[list, operator.add]       # reducer: concatenate updates

def web(state: State):
    return {"results": [f"web hit for {state['query']}"]}

def docs(state: State):
    return {"results": [f"docs hit for {state['query']}"]}

graph = StateGraph(State)
graph.add_node("web", web)
graph.add_node("docs", docs)
graph.add_edge(START, "web")                      # both run in the same step (fan-out)
graph.add_edge(START, "docs")
graph.add_edge("web", END)
graph.add_edge("docs", END)
print(graph.compile().invoke({"query": "refund policy", "results": []}))

✓ Ran with langgraph 1.2.24.

What it printed
{'query': 'refund policy', 'results': ['docs hit for refund policy', 'web hit for refund policy']}

Under the hood

What the library does for you, with its real classes

What happens without a reducer, and what add_messages does: append, replace by id, delete with RemoveMessage.

python
from typing import TypedDict
from langchain.messages import AIMessage, HumanMessage, RemoveMessage
from langgraph.errors import InvalidUpdateError
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages

class NoReducer(TypedDict):
    results: list                               # Step 4: no reducer -> "last write wins"

g = StateGraph(NoReducer)
g.add_node("web", lambda s: {"results": ["web"]})
g.add_node("docs", lambda s: {"results": ["docs"]})
g.add_edge(START, "web")
g.add_edge(START, "docs")
g.add_edge("web", END)
g.add_edge("docs", END)
try:
    g.compile().invoke({"results": []})
except InvalidUpdateError as err:
    print("two writes, no reducer:", str(err).split(".")[0])

# Steps 2-3: add_messages(current, update)
history = [HumanMessage("hi", id="1"), AIMessage("draft", id="2")]
print([m.content for m in add_messages(history, [AIMessage("hello!", id="3")])])     # new id -> append
print([m.content for m in add_messages(history, [AIMessage("final", id="2")])])      # same id -> replace
print([m.content for m in add_messages(history, [RemoveMessage(id="1")])])           # RemoveMessage -> delete

✓ Ran with langchain 1.5.2, langgraph 1.2.24.

What it printed
two writes, no reducer: At key 'results': Can receive only one value per step
['hi', 'draft', 'hello!']
['hi', 'final']
['draft']

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import itertools, operator

_ids = itertools.count(1)
def msg(role, text, id=None):
    return {"id": id or f"m{next(_ids)}", "role": role, "text": text}

def add_messages(current, new):
    # Step 3: append new messages, but a message with an existing id REPLACES that message
    merged = list(current)
    position = {m["id"]: i for i, m in enumerate(merged)}
    for m in new:
        if m["id"] in position:
            merged[position[m["id"]]] = m
        else:
            position[m["id"]] = len(merged)
            merged.append(m)
    return merged

# Step 1: the schema annotates keys with reducers:
#   messages: Annotated[list, add_messages]   sources: Annotated[list, operator.add]   status: str
REDUCERS = {"messages": add_messages, "sources": operator.add}

def apply(state, update, node):
    # Step 2: for each key in the update, call reducer(current, new)
    # Step 4: keys without a reducer simply take the new value
    for key, value in update.items():
        reducer = REDUCERS.get(key)
        state[key] = reducer(state.get(key, []), value) if reducer else value
    shown = {k: ([m["id"] + ":" + m["text"] for m in v] if k == "messages" else v) for k, v in state.items()}
    print(f"after {node:9} {shown}")

state = {}
apply(state, {"messages": [msg("user", "hi")], "status": "start"}, "input")
apply(state, {"messages": [msg("ai", "draft", id="a1")], "sources": ["doc1"], "status": "drafted"}, "writer")
apply(state, {"sources": ["doc2"]}, "retriever")
apply(state, {"messages": [msg("ai", "final", id="a1")], "status": "done"}, "editor")   # same id -> replaced

✓ Ran with plain Python 3.9+.

What it prints
after input     {'messages': ['m1:hi'], 'status': 'start'}
after writer    {'messages': ['m1:hi', 'a1:draft'], 'status': 'drafted', 'sources': ['doc1']}
after retriever {'messages': ['m1:hi', 'a1:draft'], 'status': 'drafted', 'sources': ['doc1', 'doc2']}
after editor    {'messages': ['m1:hi', 'a1:final'], 'status': 'done', 'sources': ['doc1', 'doc2']}
