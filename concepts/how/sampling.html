How does sampling (temperature, top-k, top-p) work?

In one lineScores are divided by the temperature, turned into probabilities, cut down to the most likely tokens, and then one token is drawn at random.

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

Step by step
  1. Logits are raw scores for every token in the vocabulary.
  2. Dividing by a temperature below 1 exaggerates the differences (more focused); above 1 flattens them (more random). Temperature 0 means always taking the top token (greedy).
  3. Softmax converts the scores into probabilities that add up to 1.
  4. Top-k keeps only the k most likely tokens; top-p keeps the smallest set whose probabilities add up to p.
  5. One token is drawn at random from what's left, weighted by probability.
Key details
  • Extraction and classification: temperature around 0. Creative writing: around 0.7–1.
  • Tune temperature or top-p, rarely both.
  • Even greedy decoding can vary slightly between runs because of batching and floating-point order on the server.

Use it

What you'd write at work

Open models and many APIs take temperature/top_p. Current Claude models don't accept them any more: you steer those with the prompt and effort instead.

python
from transformers import AutoModelForCausalLM, AutoTokenizer, set_seed

name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name)
messages = [{"role": "user", "content": "Suggest a name for a coffee shop. Reply with the name only."}]
inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt")

set_seed(0)
for temperature in (0.2, 1.5):
    for _ in range(3):
        out = model.generate(**inputs, do_sample=True, temperature=temperature, top_p=0.9, max_new_tokens=12)
        reply = tok.decode(out[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True)
        print(f"temperature {temperature}: {reply.strip()}")

Under the hood

What the library does for you, with its real classes

What do_sample, temperature and top_p do to the model's real next-token scores.

python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name).eval()
with torch.no_grad():
    logits = model(**tok("The most popular fruit in the world is the", return_tensors="pt")).logits[0, -1].float()   # Step 1

def top5(probs):
    p, i = torch.topk(probs, 5)
    return ", ".join(f"{tok.decode(int(t))!r} {v:.2f}" for v, t in zip(p, i))

for T in (0.5, 1.0, 1.5):                       # Step 2: divide by temperature; Step 3: softmax
    print(f"T={T}: {top5((logits / T).softmax(-1))}")

probs = logits.softmax(-1)
sorted_p, order = probs.sort(descending=True)
keep = (sorted_p.cumsum(0) - sorted_p) < 0.9    # Step 4: top-p - smallest set reaching 90%
print(f"top-p 0.9 keeps {int(keep.sum())} of {probs.numel():,} tokens")
filtered = torch.zeros_like(probs)
filtered[order[keep]] = sorted_p[keep]
torch.manual_seed(0)
picks = torch.multinomial(filtered / filtered.sum(), 6, replacement=True)   # Step 5: weighted draw
print("6 draws:", [tok.decode(int(t)) for t in picks])

✓ Ran with torch 2.15.0, transformers 5.24.0.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import math, random
random.seed(1)

# Step 1: raw scores (logits) for the next token after "The weather today is"
logits = {"sunny": 3.0, "cloudy": 2.5, "rainy": 2.0, "cold": 1.0, "purple": -1.0}

def softmax(scores, temperature):
    # Step 2: divide by the temperature. Step 3: softmax -> probabilities that add up to 1
    exps = {t: math.exp(s / temperature) for t, s in scores.items()}
    total = sum(exps.values())
    return {t: e / total for t, e in exps.items()}

for temp in (0.2, 1.0, 2.0):
    probs = softmax(logits, temp)
    print(f"T={temp}: " + "  ".join(f"{t} {p:.2f}" for t, p in probs.items()))

# Step 4: top-p keeps the smallest set of tokens whose probabilities reach p
def top_p(probs, p=0.9):
    kept, total = {}, 0.0
    for tok, pr in sorted(probs.items(), key=lambda kv: -kv[1]):
        kept[tok] = pr
        total += pr
        if total >= p:
            break
    return kept

kept = top_p(softmax(logits, 1.0), 0.9)
print("top-p 0.9 keeps:", list(kept))
# Step 5: draw one token at random, weighted by probability
draws = [random.choices(list(kept), weights=list(kept.values()))[0] for _ in range(10)]
print("10 draws:", draws)
print("temperature 0 (greedy) always picks:", max(logits, key=logits.get))

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • On APIs that expose them (OpenAI-style APIs, local servers like vLLM), ask for logprobs=True, top_logprobs=5 and print the alternatives for each token. Current Claude models no longer accept temperature/top_p: you steer them with the prompt and effort instead.
  • Hugging Face: model.generate(..., do_sample=True, temperature=0.7, top_p=0.9); set do_sample=False for greedy decoding.
  • Run the same prompt 5 times at temperature 0 and at 1.0 to feel the difference in variety.
