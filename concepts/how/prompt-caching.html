How does prompt caching work?

In one lineWhen requests start with the same long prefix, the provider keeps the computed KV cache for that prefix, so later requests skip that work and cost less.

Step by step
  1. The first request computes the KV cache for the whole prompt as usual.
  2. The cache for the prefix is kept for a while (minutes to an hour, depending on the provider).
  3. A later request whose prompt starts with exactly the same tokens reuses it.
  4. Only the new part (e.g. the new question) is processed, so time to first token drops and cached input tokens are billed at a discount.
Key details
  • Put stable content first (instructions, tools, documents) and variable content last.
  • Any change early in the prompt (even a timestamp) breaks the match for everything after it.
  • Some providers cache automatically; others need explicit cache markers.

Use it

What you'd write at work

Mark the long, unchanging part as cacheable; later requests that start with the same bytes read it from cache. The usage fields show whether it worked.

python
import anthropic

client = anthropic.Anthropic()
POLICY = open("policy.md").read()               # a long, stable document (keep timestamps out of it)

def ask(question):
    return client.beta.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        cache_control={"type": "ephemeral"},    # cache everything up to the last cacheable block
        system=[{"type": "text", "text": "Answer from this policy:\n" + POLICY}],
        messages=[{"role": "user", "content": question}],
        betas=["server-side-fallback-2026-07-01"],
        fallbacks="default",
    )

for q in ["Where is my order?", "How do refunds work?"]:
    u = ask(q).usage
    print(f"{q!r:22} written to cache {u.cache_creation_input_tokens:5}, read from cache {u.cache_read_input_tokens:5}, uncached {u.input_tokens}")

✓ Ran with anthropic 2.13.0 · with a mocked Anthropic HTTP endpoint (the real SDK validated the request).

What it printed
'Where is my order?'   written to cache  5200, read from cache     0, uncached 12
'How do refunds work?' written to cache     0, read from cache  5200, uncached 14

Under the hood

What the library does for you, with its real classes

What the provider keeps: the KV cache of the prefix. Here a real model computes it once, then answers two questions by processing only their new tokens - with the same result as processing everything.

python
import copy
import time
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, DynamicCache

name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, dtype=torch.float32).eval()   # float32: exact comparison
prefix = tok("You are a support bot. Policy: " + "Refunds within 30 days. " * 60, return_tensors="pt").input_ids

with torch.no_grad():
    start = time.time()
    prefix_cache = model(prefix, cache=DynamicCache(), use_cache=True).cache     # Steps 1-2: compute once, keep
    print(f"prefix: {prefix.shape[1]} tokens cached in {time.time() - start:.2f}s")
    for q in ["Question: can I get a refund?", "Question: how long do I have?"]:
        q_ids = tok(q, add_special_tokens=False, return_tensors="pt").input_ids
        start = time.time()
        full = model(torch.cat([prefix, q_ids], dim=1)).logits[0, -1]            # no cache: everything
        t_full = time.time() - start
        start = time.time()
        cached = model(q_ids, cache=copy.deepcopy(prefix_cache)).logits[0, -1]   # Steps 3-4: only new tokens
        t_cached = time.time() - start
        same = torch.allclose(full, cached, atol=1e-3)
        print(f"{q!r}: full {t_full:.2f}s vs cached {t_cached:.2f}s ({q_ids.shape[1]} new tokens), same answer: {same}")

✓ Ran with torch 2.15.0, transformers 5.24.0.

What it printed
prefix: 489 tokens cached in 0.57s
'Question: can I get a refund?': full 0.62s vs cached 0.11s (8 new tokens), same answer: True
'Question: how long do I have?': full 0.41s vs cached 0.08s (8 new tokens), same answer: True

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# A provider-side prefix cache: the KV cache for a prompt prefix is kept, keyed by its exact tokens.
import hashlib
cache = {}

def request(prompt, prefix_tokens):
    toks = prompt.split()
    prefix = toks[:prefix_tokens]
    key = hashlib.sha256(" ".join(prefix).encode()).hexdigest()[:10]
    if key in cache:
        # Step 3-4: same prefix -> reuse its KV cache; only the new part is processed
        processed, reused = len(toks) - len(prefix), len(prefix)
    else:
        # Step 1-2: compute the KV cache for the whole prompt, keep the prefix part for a while
        cache[key] = "KV tensors for the prefix"
        processed, reused = len(toks), 0
    print(f"{'HIT ' if reused else 'MISS'} key {key}: processed {processed:4} tokens, reused {reused}")

SYSTEM = "You are a support bot. " + "policy " * 2000     # a long, unchanging prefix
n = len(SYSTEM.split())
request(SYSTEM + "Question: where is my order?", n)
request(SYSTEM + "Question: how do refunds work?", n)
# change ONE early token and the prefix no longer matches
request("You are a SUPPORT bot. " + "policy " * 2000 + "Question: hi", n)

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • Anthropic: mark the stable prefix with cache_control; the response’s usage shows cache_creation_input_tokens on the first call and cache_read_input_tokens on later ones.
  • OpenAI-style APIs report cached tokens in usage.prompt_tokens_details.cached_tokens (automatic above a minimum prompt length).
  • Change one character near the start of the prompt (a timestamp, a user name) and watch the cache hits drop to zero: keep the variable parts at the end.
