How does prompt caching work?

In one lineWhen requests start with the same long prefix, the provider keeps the computed KV cache for that prefix, so later requests skip that work and cost less.

Step by step
  1. The first request computes the KV cache for the whole prompt as usual.
  2. The cache for the prefix is kept for a while (minutes to an hour, depending on the provider).
  3. A later request whose prompt starts with exactly the same tokens reuses it.
  4. Only the new part (e.g. the new question) is processed, so time to first token drops and cached input tokens are billed at a discount.
Key details
  • Put stable content first (instructions, tools, documents) and variable content last.
  • Any change early in the prompt (even a timestamp) breaks the match for everything after it.
  • Some providers cache automatically; others need explicit cache markers.
