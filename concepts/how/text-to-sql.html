How does text-to-SQL work?

In one lineThe model gets the database schema and the question, writes a SQL query, your code runs it safely, and the model turns the result rows into an answer.

Step by step
  1. The prompt includes the relevant tables and columns, their meaning, and a few example queries.
  2. The model writes a SQL query for the question.
  3. Code validates it: read-only, only allowed tables, a row limit, and a timeout.
  4. It runs against a read replica or a restricted user, never with write access.
  5. On an error, the error message goes back to the model to fix the query.
  6. The model summarizes the result, and showing the SQL lets users check it.
Key details
  • Use this instead of RAG when the answer needs aggregation (totals, counts, trends).
  • For big schemas, retrieve only the relevant tables first.
  • Never let the model's SQL run with permissions the user doesn't have.
