How does text-to-SQL work?

In one lineThe model gets the database schema and the question, writes a SQL query, your code runs it safely, and the model turns the result rows into an answer.

Step by step
  1. The prompt includes the relevant tables and columns, their meaning, and a few example queries.
  2. The model writes a SQL query for the question.
  3. Code validates it: read-only, only allowed tables, a row limit, and a timeout.
  4. It runs against a read replica or a restricted user, never with write access.
  5. On an error, the error message goes back to the model to fix the query.
  6. The model summarizes the result, and showing the SQL lets users check it.
Key details
  • Use this instead of RAG when the answer needs aggregation (totals, counts, trends).
  • For big schemas, retrieve only the relevant tables first.
  • Never let the model's SQL run with permissions the user doesn't have.

Use it

What you'd write at work

An agent with one read-only SQL tool. The first query fails, the error goes back, the model fixes it: the loop from the diagram, live.

python
import sqlite3
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool

with sqlite3.connect("shop.db") as db:
    db.executescript("""CREATE TABLE orders (id INTEGER, customer TEXT, amount REAL);
        INSERT INTO orders VALUES (1,'acme',120), (2,'globex',80), (3,'acme',200);""")

@tool
def run_sql(query: str) -> str:
    """Run one read-only SQLite SELECT on table orders(id, customer, amount). Returns rows or an error."""
    if not query.lstrip().lower().startswith("select"):
        return "Error: only SELECT queries are allowed"
    try:
        with sqlite3.connect("file:shop.db?mode=ro", uri=True) as conn:      # read-only connection
            return str(conn.execute(query + " LIMIT 100").fetchall())
    except sqlite3.Error as err:
        return f"Error: {err}"                       # goes back to the model so it can fix the query

agent = create_agent(init_chat_model("anthropic:claude-opus-5-5"), [run_sql],
                     system_prompt="Answer questions about orders with SQL. Show the SQL you used.")
result = agent.invoke({"messages": [("user", "Which customer spent the most?")]})
for m in result["messages"][1:]:
    print(f"{m.type:5}", m.tool_calls[0]["args"]["query"] if getattr(m, "tool_calls", None) else m.content)

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

ai    acme spent the most: 320 in total. SQL: SELECT customer, SUM(amount) AS total FROM orders GROUP BY customer ORDER BY total DESC

Under the hood

What the library does for you, with its real classes

The safety rails the tool relies on, at the database level: read-only mode, a time limit and the query plan.

python
import sqlite3
import time

conn = sqlite3.connect(":memory:")
conn.executescript("""CREATE TABLE orders (id INTEGER PRIMARY KEY, customer TEXT, amount REAL);
    INSERT INTO orders VALUES (1,'acme',120), (2,'globex',80), (3,'acme',200);""")
schema = conn.execute("SELECT sql FROM sqlite_master WHERE type='table'").fetchall()   # Step 1: for the prompt
print("schema for the prompt:", schema[0][0])

conn.execute("PRAGMA query_only = ON")                       # Step 4: this connection can't write
try:
    conn.execute("DELETE FROM orders")
except sqlite3.OperationalError as err:
    print("write blocked:", err)

deadline = time.time() + 2.0                                 # Step 3: a time limit
conn.set_progress_handler(lambda: time.time() > deadline, 10_000)

sql = "SELECT customer, SUM(amount) AS total FROM orders GROUP BY customer ORDER BY total DESC"
print("plan:", conn.execute("EXPLAIN QUERY PLAN " + sql).fetchall())   # catch full scans on big tables
print("rows:", conn.execute(sql + " LIMIT 100").fetchall())

✓ Ran with Python 3.12.14.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Uses SQLite from the standard library.
import re, sqlite3

db = sqlite3.connect(":memory:")
db.executescript("""
CREATE TABLE orders (id INTEGER, customer TEXT, amount REAL, created TEXT);
INSERT INTO orders VALUES (1,'acme',120,'2026-10-02'), (2,'globex',80,'2026-10-15'),
                          (3,'acme',200,'2026-11-01'), (4,'initech',50,'2026-11-03');
""")
ALLOWED_TABLES = {"orders"}

# Step 1: the prompt carries the schema (real systems add column meanings and example queries)
schema = db.execute("SELECT sql FROM sqlite_master WHERE name='orders'").fetchone()[0]
question = "Which customer spent the most in total?"
prompt = f"Schema:\n{schema}\n\nWrite one SQLite query for: {question}"

# Step 2: the model writes SQL (stubbed: the first attempt has a mistake, the second is fixed)
attempts = iter([
    "SELECT customer, SUM(amount) AS total FROM order GROUP BY customer ORDER BY total DESC",
    "SELECT customer, SUM(amount) AS total FROM orders GROUP BY customer ORDER BY total DESC",
])

def validate(sql):
    # Step 3: one read-only SELECT, allowed tables only, always a row limit
    if not re.match(r"(?is)^\s*select\b", sql) or ";" in sql.rstrip(";"):
        raise ValueError("only a single SELECT is allowed")
    for table in re.findall(r"(?i)\b(?:from|join)\s+(\w+)", sql):
        if table.lower() not in ALLOWED_TABLES:
            raise ValueError(f"table '{table}' is not allowed (allowed: {sorted(ALLOWED_TABLES)})")
    return sql + " LIMIT 100"

sql = next(attempts)
for attempt in (1, 2):
    try:
        safe = validate(sql)
        rows = db.execute(safe).fetchall()   # Step 4: in production, a read-only user on a replica
        print(f"attempt {attempt} ran: {safe}")
        break
    except Exception as err:
        # Step 5: the error goes back to the model so it can fix the query
        print(f"attempt {attempt} rejected: {err} -> error sent back to the model")
        sql = next(attempts)

# Step 6: summarize, and show the SQL so users can check it
print("rows:", rows)
print(f"answer: {rows[0][0]} spent the most ({rows[0][1]:.0f}).")

✓ Ran with plain Python 3.9+.

What it prints
attempt 1 rejected: table 'order' is not allowed (allowed: ['orders']) -> error sent back to the model
attempt 2 ran: SELECT customer, SUM(amount) AS total FROM orders GROUP BY customer ORDER BY total DESC LIMIT 100
rows: [('acme', 320.0), ('globex', 80.0), ('initech', 50.0)]
answer: acme spent the most (320).
Watch it in a real system
  • Log the generated SQL for every question, next to the answer; show it to users too, so they can check it.
  • Run EXPLAIN on generated queries in development to catch slow full-table scans before they reach production.
  • Connect with a read-only database role and a statement timeout, then try a prompt that asks it to delete something, and confirm the database refuses.
