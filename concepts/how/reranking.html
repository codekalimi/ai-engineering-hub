How does reranking work (bi-encoder vs cross-encoder)?

In one lineRetrieval embeds the query and documents separately: fast but coarse. A reranker reads the query and each candidate together: slower but much more accurate, so it only runs on a short list.

Step by step
  1. A bi-encoder embeds documents ahead of time, so search is just a vector comparison and scales to millions of documents.
  2. But the query and document never see each other, so subtle relevance can be missed.
  3. A cross-encoder takes the query and one document as a single input and outputs a relevance score, capturing fine-grained interactions.
  4. Because it must run once per candidate at query time, it's only used to rerank the top 20–100 results.
Key details
  • Typical effect: noticeably better precision in the top few results.
  • Cost: tens to hundreds of milliseconds per query.
  • An LLM can also act as a reranker, at a higher cost.
