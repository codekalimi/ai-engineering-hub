How does reranking work (bi-encoder vs cross-encoder)?

In one lineRetrieval embeds the query and documents separately: fast but coarse. A reranker reads the query and each candidate together: slower but much more accurate, so it only runs on a short list.

Step by step
  1. A bi-encoder embeds documents ahead of time, so search is just a vector comparison and scales to millions of documents.
  2. But the query and document never see each other, so subtle relevance can be missed.
  3. A cross-encoder takes the query and one document as a single input and outputs a relevance score, capturing fine-grained interactions.
  4. Because it must run once per candidate at query time, it's only used to rerank the top 20–100 results.
Key details
  • Typical effect: noticeably better precision in the top few results.
  • Cost: tens to hundreds of milliseconds per query.
  • An LLM can also act as a reranker, at a higher cost.

Use it

What you'd write at work

A real cross-encoder (an 80 MB model) reranking candidates that a fast first-stage search returned.

python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L6-v2")
query = "How do I stop my subscription?"
candidates = ["Subscription plans start at 10 dollars a month.",          # shares words, wrong answer
              "Stop words are removed before indexing.",                  # shares words, unrelated
              "To cancel, open Settings and choose End membership."]      # no shared words, right answer

for hit in reranker.rank(query, candidates):
    print(f"{hit['score']:6.2f}  {candidates[hit['corpus_id']]}")

✓ Ran with sentence-transformers 6.3.0.

Under the hood

What the library does for you, with its real classes

What CrossEncoder does: tokenize the query and document TOGETHER as one input, run a transformer classifier, read one relevance score per pair.

python
import torch
from transformers import AutoModelForSequenceClassification, AutoTokenizer

name = "cross-encoder/ms-marco-MiniLM-L6-v2"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name).eval()

query = "How do I stop my subscription?"
candidates = ["Subscription plans start at 10 dollars a month.",
              "Stop words are removed before indexing.",
              "To cancel, open Settings and choose End membership."]
batch = tok([query] * len(candidates), candidates, padding=True, return_tensors="pt")   # Step 3: pairs
print("one input:", tok.decode(batch["input_ids"][0], skip_special_tokens=False).replace(" [PAD]", ""))

with torch.no_grad():
    scores = model(**batch).logits.squeeze(-1)          # one number per (query, document) pair
for s, c in sorted(zip(scores.tolist(), candidates), reverse=True):
    print(f"{s:6.2f}  {c}")
# Step 4: one forward pass per candidate - which is why you only rerank the top 20-100

✓ Ran with torch 2.15.0, transformers 5.24.0.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import re
words = lambda t: re.findall(r"[a-z]+", t.lower())

query = "flights from Delhi to Mumbai"
candidates = [
    "Flights from Mumbai to Delhi every morning",
    "Mumbai and Delhi hotel deals",
    "Delhi to Mumbai flights depart every hour",
]

# Step 1: bi-encoder - each text becomes a vector ON ITS OWN (here: a set of words), ahead of time
def embed(text): return set(words(text))
def bi_score(q, d): return len(q & d) / len(q | d)
doc_vectors = [embed(d) for d in candidates]
q_vec = embed(query)
print("bi-encoder (fast, but query and document never meet):")
for d, v in sorted(zip(candidates, doc_vectors), key=lambda x: -bi_score(q_vec, x[1])):
    print(f"  {bi_score(q_vec, v):.2f}  {d}")

# Step 2-3: cross-encoder - reads the query and document TOGETHER, so it can see that
# the direction of travel matters. (A real one is a transformer that outputs a score.)
def cross_score(q, d):
    qw, dw = words(q), words(d)
    overlap = len(set(qw) & set(dw)) / len(set(qw))
    right_direction = {"delhi", "mumbai"} <= set(dw) and dw.index("delhi") < dw.index("mumbai")
    return round(0.4 * overlap + 0.4 * right_direction + 0.2 * ("flights" in dw), 2)

# Step 4: run it only on the top candidates - one model call per pair
print("cross-encoder rerank:")
for d in sorted(candidates, key=lambda d: -cross_score(query, d)):
    print(f"  {cross_score(query, d):.2f}  {d}")

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • sentence-transformers: CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2").predict([(query, doc) for doc in candidates]) returns one relevance score per pair.
  • Hosted rerankers (Cohere, Voyage, Jina and others) take a query plus a list of documents and return them re-sorted with scores; log the order before and after.
  • Measure it: recall@5 or MRR on a small labelled set, with and without the reranker.
