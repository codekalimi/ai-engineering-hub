How does parent-document (small-to-big) retrieval work?

In one lineSearch over small, precise chunks, but hand the model the larger section they came from, so you get precise matching and enough context.

Step by step
  1. Each document is split twice: into large parent sections and small child chunks, each child pointing to its parent.
  2. Only the small chunks are embedded, so similarity search matches precisely.
  3. When a child matches, the system retrieves its parent section instead.
  4. The model gets the full surrounding context, which improves answers that need more than one sentence.
Key details
  • De-duplicate parents when several children from the same section match.
  • A variant is "sentence window": retrieve a sentence and include a few sentences around it.

Use it

What you'd write at work

Search small chunks, return the big section they came from.

python
from langchain.embeddings import init_embeddings
from langchain_classic.retrievers import ParentDocumentRetriever
from langchain_core.documents import Document
from langchain_core.stores import InMemoryStore
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_text_splitters import RecursiveCharacterTextSplitter

retriever = ParentDocumentRetriever(
    vectorstore=InMemoryVectorStore(init_embeddings("openai:text-embedding-3-small")),   # small chunks
    docstore=InMemoryStore(),                                                           # full parents
    child_splitter=RecursiveCharacterTextSplitter(chunk_size=60, chunk_overlap=0),
)
retriever.add_documents([
    Document("Refunds. Customers can request a refund within 30 days. Refunds go back to the original "
             "payment method. Digital downloads are refundable only if not yet downloaded."),
    Document("Shipping. Orders ship within 2 business days. International orders may take 3 weeks."),
])
print(retriever.invoke("refund for an e-book I already downloaded")[0].page_content)

✓ Ran with langchain 1.5.2, langchain-classic 1.1.0, langchain-core 1.8.4, langchain-text-splitters 1.2.0 · with a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

What it printed
Refunds. Customers can request a refund within 30 days. Refunds go back to the original payment method. Digital downloads are refundable only if not yet downloaded.

Under the hood

What the library does for you, with its real classes

The same thing by hand with the real stores: children carry their parent's id; search children; fetch parents by id.

python
import uuid
from langchain.embeddings import init_embeddings
from langchain_core.documents import Document
from langchain_core.stores import InMemoryStore
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_text_splitters import RecursiveCharacterTextSplitter

parents = [Document("Refunds. Customers can request a refund within 30 days. Refunds go back to the original "
                    "payment method. Digital downloads are refundable only if not yet downloaded."),
           Document("Shipping. Orders ship within 2 business days. International orders may take 3 weeks.")]
vectors, docstore = InMemoryVectorStore(init_embeddings("openai:text-embedding-3-small")), InMemoryStore()
splitter = RecursiveCharacterTextSplitter(chunk_size=60, chunk_overlap=0)

for parent in parents:                                    # Step 1: split twice, link child -> parent
    pid = str(uuid.uuid4())
    docstore.mset([(pid, parent)])
    children = splitter.split_documents([parent])
    for c in children:
        c.metadata["doc_id"] = pid
    vectors.add_documents(children)                       # Step 2: only children are embedded

hit = vectors.similarity_search("refund for an e-book I already downloaded", k=1)[0]
print("matched child:", repr(hit.page_content))
print("returned parent:", docstore.mget([hit.metadata["doc_id"]])[0].page_content)   # Steps 3-4

✓ Ran with langchain 1.5.2, langchain-core 1.8.4, langchain-text-splitters 1.2.0 · with a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

What it printed
matched child: 'Refunds go back to the original payment method. Digital'
returned parent: Refunds. Customers can request a refund within 30 days. Refunds go back to the original payment method. Digital downloads are refundable only if not yet downloaded.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import re
words = lambda t: set(re.findall(r"[a-z0-9]+", t.lower()))

# Step 1: split each document twice - big parent sections, small child chunks that point to a parent
parents = {
    "P1": "Refunds. Customers can request a refund within 30 days. Refunds go back to the original "
          "payment method. Digital downloads are refundable only if not yet downloaded.",
    "P2": "Shipping. Orders ship within 2 business days. Express shipping costs extra. "
          "International orders may take up to 3 weeks.",
}
children = [{"text": s, "parent": pid} for pid, text in parents.items() for s in text.split(". ")]
print(f"{len(parents)} parents -> {len(children)} child chunks")

# Step 2: only the small chunks are searched, so matching is precise
question = "Can I get a refund for an e-book I already downloaded?"
best = max(children, key=lambda c: len(words(question) & words(c["text"])))
print("best child chunk:", repr(best["text"]), "-> parent", best["parent"])

# Step 3-4: return the parent section instead: it holds the rule the child chunk is missing
print("context sent to the LLM:", parents[best["parent"]])

✓ Ran with plain Python 3.9+.

What it prints
2 parents -> 8 child chunks
best child chunk: 'Customers can request a refund within 30 days' -> parent P1
context sent to the LLM: Refunds. Customers can request a refund within 30 days. Refunds go back to the original payment method. Digital downloads are refundable only if not yet downloaded.

  • A simple DIY version: store parent_id in each chunk’s metadata, search chunks, then fetch parents by id and de-duplicate.
