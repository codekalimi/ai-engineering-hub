How does parent-document (small-to-big) retrieval work?

In one lineSearch over small, precise chunks, but hand the model the larger section they came from, so you get precise matching and enough context.

Step by step
  1. Each document is split twice: into large parent sections and small child chunks, each child pointing to its parent.
  2. Only the small chunks are embedded, so similarity search matches precisely.
  3. When a child matches, the system retrieves its parent section instead.
  4. The model gets the full surrounding context, which improves answers that need more than one sentence.
Key details
  • De-duplicate parents when several children from the same section match.
  • A variant is "sentence window": retrieve a sentence and include a few sentences around it.
Behind the scenes

See it run

A tiny from-scratch version of what really happens. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: plain Python, nothing to install.

python3 · standard library only
import re
words = lambda t: set(re.findall(r"[a-z0-9]+", t.lower()))

# Step 1: split each document twice - big parent sections, small child chunks that point to a parent
parents = {
    "P1": "Refunds. Customers can request a refund within 30 days. Refunds go back to the original "
          "payment method. Digital downloads are refundable only if not yet downloaded.",
    "P2": "Shipping. Orders ship within 2 business days. Express shipping costs extra. "
          "International orders may take up to 3 weeks.",
}
children = [{"text": s, "parent": pid} for pid, text in parents.items() for s in text.split(". ")]
print(f"{len(parents)} parents -> {len(children)} child chunks")

# Step 2: only the small chunks are searched, so matching is precise
question = "Can I get a refund for an e-book I already downloaded?"
best = max(children, key=lambda c: len(words(question) & words(c["text"])))
print("best child chunk:", repr(best["text"]), "-> parent", best["parent"])

# Step 3-4: return the parent section instead: it holds the rule the child chunk is missing
print("context sent to the LLM:", parents[best["parent"]])
What it prints
2 parents -> 8 child chunks
best child chunk: 'Customers can request a refund within 30 days' -> parent P1
context sent to the LLM: Refunds. Customers can request a refund within 30 days. Refunds go back to the original payment method. Digital downloads are refundable only if not yet downloaded.
Watch it in a real system

  • A simple DIY version: store parent_id in each chunk’s metadata, search chunks, then fetch parents by id and de-duplicate.
  • Compare answers using only the matched chunk vs the full parent for questions whose answer spans several sentences.
