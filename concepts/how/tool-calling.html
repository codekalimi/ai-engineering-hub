How does tool (function) calling work?

In one lineThe model never runs code. It returns a structured request to call a tool; your app runs the tool and sends the result back for the model to use.

Step by step
  1. Your app sends the conversation plus the tool schemas: name, description and argument schema for each tool.
  2. The model decides a tool would help and replies with a structured tool call instead of text.
  3. Your code (or the framework) runs the matching function with those arguments.
  4. The result goes back to the model as a tool message, linked by the tool call ID.
  5. The model uses the result to write its answer, or asks for another tool.
Key details
  • The tool's name, description and argument schema are effectively part of the prompt: write them for the model.
  • Models can request several tool calls in one turn (parallel tool calls).
  • Validate arguments in code; never execute them blindly.

1

Use it

What you'd write at work

Decorate a function, bind it, and the model can ask for it. You run it; the result goes back as a ToolMessage.

python
from langchain.chat_models import init_chat_model
from langchain.messages import HumanMessage
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Current weather for a city."""
    return {"Pune": "Rain, 24C"}.get(city, "unknown")

model = init_chat_model("anthropic:claude-opus-5-5").bind_tools([get_weather])
messages = [HumanMessage("Do I need an umbrella in Pune today?")]

ai = model.invoke(messages)
print("tool calls:", ai.tool_calls)
messages += [ai] + [get_weather.invoke(call) for call in ai.tool_calls]   # invoking with the call -> a ToolMessage
print("tool result:", messages[-1].content, "| linked to", messages[-1].tool_call_id)
print("answer:", model.invoke(messages).content)

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

What it printed
tool calls: [{'name': 'get_weather', 'args': {'city': 'Pune'}, 'id': 'call_1', 'type': 'tool_call'}]
tool result: Rain, 24C | linked to call_1
answer: Yes - it's raining in Pune (24C), so take an umbrella.

Under the hood

What the library does for you, with its real classes

What LangChain translates that into: the raw Anthropic Messages API. Tools are JSON schemas; the model answers with a tool_use block; you reply with a tool_result block carrying the same id.

python
import json
import anthropic

client = anthropic.Anthropic()
tools = [{"name": "get_weather", "description": "Current weather for a city.",           # Step 1: schemas
          "input_schema": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}]
messages = [{"role": "user", "content": "Do I need an umbrella in Pune today?"}]

def ask():
    return client.beta.messages.create(model="claude-opus-5-5", max_tokens=16000, tools=tools,
                                       messages=messages, betas=["server-side-fallback-2026-07-01"], fallbacks="default")

response = ask()
print("stop_reason:", response.stop_reason)                    # Step 2: "tool_use", not text
tool_use = next(b for b in response.content if b.type == "tool_use")
print("model asked for:", tool_use.name, tool_use.input, "id", tool_use.id)

result = {"Pune": "Rain, 24C"}[tool_use.input["city"]]           # Step 3: YOUR code runs it
messages += [{"role": "assistant", "content": response.content},  # Step 4: echo the call, then the result
             {"role": "user", "content": [{"type": "tool_result", "tool_use_id": tool_use.id, "content": result}]}]
print("sent back:", json.dumps(messages[-1]))
print("answer:", ask().content[0].text)                          # Step 5

✓ Ran with anthropic 2.13.0 · with a mocked Anthropic HTTP endpoint (the real SDK validated the request).

What it printed
stop_reason: tool_use
model asked for: get_weather {'city': 'Pune'} id toolu_01
sent back: {"role": "user", "content": [{"type": "tool_result", "tool_use_id": "toolu_01", "content": "Rain, 24C"}]}
answer: Yes - it's raining in Pune (24C), so take an umbrella.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# The JSON that actually goes back and forth. Field names vary a little by provider; the shape doesn't.
import json

def get_weather(city):
    return {"Pune": "Rain, 24C", "Delhi": "Sunny, 31C"}.get(city, "unknown")
TOOLS = {"get_weather": get_weather}

# Step 1: your app sends the conversation plus the tool schemas
request = {
    "messages": [{"role": "user", "content": "Do I need an umbrella in Pune today?"}],
    "tools": [{"name": "get_weather", "description": "Current weather for a city",
               "input_schema": {"type": "object", "properties": {"city": {"type": "string"}},
                                "required": ["city"]}}],
}
print("REQUEST ->", json.dumps(request)[:110], "...")

def fake_model(req):
    last = req["messages"][-1]
    if last["role"] == "user":
        # Step 2: the model replies with a structured tool call instead of text
        return {"role": "assistant", "tool_calls": [{"id": "call_1", "name": "get_weather", "arguments": {"city": "Pune"}}]}
    # Step 5: the model uses the result to write its answer
    return {"role": "assistant", "content": f"The forecast says {last['content']}, so yes, take an umbrella."}

reply = fake_model(request)
print("MODEL   ->", json.dumps(reply))
for call in reply["tool_calls"]:
    # Step 3: YOUR code runs the function. The model never executes anything.
    result = TOOLS[call["name"]](**call["arguments"])
    # Step 4: the result goes back as a tool message, linked by the tool call id
    request["messages"] += [reply, {"role": "tool", "tool_call_id": call["id"], "content": result}]
    print("TOOL    ->", json.dumps(request["messages"][-1]))
print("MODEL   ->", fake_model(request)["content"])

✓ Ran with plain Python 3.9+.

What it prints

MODEL   -> {"role": "assistant", "tool_calls": [{"id": "call_1", "name": "get_weather", "arguments": {"city": "Pune"}}]}
TOOL    -> {"role": "tool", "tool_call_id": "call_1", "content": "Rain, 24C"}
MODEL   -> The forecast says Rain, 24C, so yes, take an umbrella.
Watch it in a real system
  • LangChain: ai = model.bind_tools([get_weather]).invoke("..."), then print ai.tool_calls: a list of {"name", "args", "id"} dicts. That is the model’s whole contribution.
  • Print convert_to_openai_tool(get_weather) (from langchain_core.utils.function_calling) to see the JSON schema your Python function becomes.
  • Raw SDKs: set ANTHROPIC_LOG=debug or OPENAI_LOG=debug to log each HTTP request the SDK makes; or print the response object and find the tool-call block.
