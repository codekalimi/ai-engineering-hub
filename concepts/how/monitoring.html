How does production monitoring of an LLM app work?

In one lineEvery request is traced with its inputs, retrieved context, outputs, tokens, cost and latency; dashboards and alerts watch these metrics, and feedback flows back into the eval set.

How to read this diagram

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

Step by step
  1. Instrument the app so each request produces a trace with every step's input and output.
  2. Aggregate operational metrics: latency (TTFT and total), errors, tokens and cost per feature.
  3. Collect quality signals: thumbs up/down, escalations, and LLM-judge scores on a sample.
  4. Alert on regressions such as rising cost, latency or negative feedback.
  5. Add real failures to the eval dataset, fix them, and verify before redeploying.
Key details
  • Tag traces with prompt and model versions so you can compare releases.
  • Mask personal data in logs and traces.
