How does production monitoring of an LLM app work?

In one lineEvery request is traced with its inputs, retrieved context, outputs, tokens, cost and latency; dashboards and alerts watch these metrics, and feedback flows back into the eval set.

Step by step
  1. Instrument the app so each request produces a trace with every step's input and output.
  2. Aggregate operational metrics: latency (TTFT and total), errors, tokens and cost per feature.
  3. Collect quality signals: thumbs up/down, escalations, and LLM-judge scores on a sample.
  4. Alert on regressions such as rising cost, latency or negative feedback.
  5. Add real failures to the eval dataset, fix them, and verify before redeploying.
Key details
  • Tag traces with prompt and model versions so you can compare releases.
  • Mask personal data in logs and traces.

Use it

What you'd write at work

LangSmith tracing: set two environment variables and every LangChain/LangGraph run is traced. @traceable adds your own functions to the trace, with metadata to slice by.

python
import os
from langsmith import traceable
from langchain.chat_models import init_chat_model

# In production: LANGSMITH_TRACING=true and LANGSMITH_API_KEY=... (left off here, so nothing is uploaded)
os.environ.setdefault("LANGSMITH_TRACING", "false")
model = init_chat_model("anthropic:claude-opus-5-5")

@traceable(run_type="chain", name="support_answer", metadata={"prompt_version": "v2", "feature": "support-chat"})
def answer(question: str) -> str:
    return model.invoke([("system", "Answer support questions briefly."), ("human", question)]).content

print(answer("How long do refunds take?"))

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

What it printed
Refunds take 5 working days.

Under the hood

What the library does for you, with its real classes

What a tracer records per request, as a callback: latency, tokens, model and your tags, emitted as one structured log line you can aggregate and alert on.

python
import json
import time
from langchain.chat_models import init_chat_model
from langchain_core.callbacks import BaseCallbackHandler

class MetricsLogger(BaseCallbackHandler):
    def __init__(self):
        self.start = {}
    def on_chat_model_start(self, serialized, messages, *, run_id, tags=None, metadata=None, **kw):
        self.start[run_id] = (time.time(), tags, metadata or {})       # metadata arrives with the start event
    def on_llm_end(self, response, *, run_id, **kw):
        started, tags, metadata = self.start.pop(run_id)
        usage = response.generations[0][0].message.usage_metadata or {}
        record = {"latency_ms": round((time.time() - started) * 1000, 1),                  # Steps 1-2
                  "input_tokens": usage.get("input_tokens"), "output_tokens": usage.get("output_tokens"),
                  "model": metadata.get("ls_model_name"), "prompt_version": metadata.get("prompt_version"), "tags": tags}
        print(json.dumps(record))          # in production: send to your log pipeline / metrics backend

model = init_chat_model("anthropic:claude-opus-5-5")
config = {"callbacks": [MetricsLogger()], "metadata": {"prompt_version": "v2"}, "tags": ["support-chat"]}
for q in ["How long do refunds take?", "When does my order ship?"]:
    model.invoke(q, config)

✓ Ran with langchain 1.5.2, langchain-core 1.8.4 · with a scripted chat model in place of the API.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import json, random, statistics
random.seed(11)
TRACES = []

def handle_request(feature, prompt_version):
    # Step 1: one trace per request, with each step's timing and the metadata to slice by
    trace = {"feature": feature, "prompt_version": prompt_version, "spans": []}
    for name, base in [("retrieve", 0.12), ("llm", 1.1 if prompt_version == "v1" else 2.4)]:
        trace["spans"].append({"name": name, "secs": round(base * random.uniform(0.8, 1.3), 2)})
    trace["tokens"] = 900 if prompt_version == "v1" else 1900
    trace["cost_usd"] = trace["tokens"] * 3 / 1e6
    trace["thumbs_up"] = random.random() < (0.8 if prompt_version == "v1" else 0.6)   # Step 3
    TRACES.append(trace)

for _ in range(50):
    handle_request("support-chat", "v1")
for _ in range(50):
    handle_request("support-chat", "v2")          # a new prompt version was deployed
print("one trace:", json.dumps(TRACES[0]))

# Step 2: aggregate per version
for v in ("v1", "v2"):
    ts = [t for t in TRACES if t["prompt_version"] == v]
    latencies = sorted(sum(s["secs"] for s in t["spans"]) for t in ts)
    p95 = latencies[int(0.95 * len(latencies)) - 1]
    up = sum(t["thumbs_up"] for t in ts) / len(ts)
    cost = statistics.mean(t["cost_usd"] for t in ts)
    print(f"{v}: p95 latency {p95:.2f}s  cost/request {cost:.4f} USD  thumbs-up {up:.0%}")
    # Step 4: alert on regressions
    if v == "v2" and (up < 0.7 or p95 > 3):
        print("ALERT: v2 regressed -> roll back, add the bad traces to the eval set (Step 5)")

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • LangSmith or Langfuse: open one trace and read it top to bottom (prompt, retrieved context, tool calls, tokens, latency per step) before building any dashboard.
  • OpenTelemetry has GenAI semantic conventions (model, token usage, operation) so LLM spans fit into your existing tracing backend.
  • Tag every trace with prompt version, model and feature, then compare a release with the previous one on latency, cost and feedback.
