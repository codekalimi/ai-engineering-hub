How does an inference server (like vLLM) handle a request?

In one lineThe request is tokenized and queued; a scheduler admits it when there's KV-cache memory, runs prefill, then keeps it in a continuously batched decode loop, streaming tokens back.

Step by step
  1. The API layer receives the request and tokenizes the prompt.
  2. The scheduler queues it and admits it when there's enough free KV-cache memory.
  3. Prefill processes the whole prompt and fills its KV cache.
  4. The request joins the running batch; every decode step produces one token for each active request.
  5. Tokens are detokenized and streamed back; when the request finishes, its memory is freed for the next one.
Key details
  • Under memory pressure, the scheduler can pause (preempt) a request and resume it later.
  • Prefix caching skips prefill for prompt parts already in the cache.
  • Key settings: max model length, max concurrent sequences, GPU memory fraction.
