How do guardrails work?

In one lineChecks run before and after the model: input guards block injection, PII and off-policy requests; output guards catch leaks, unsafe content and ungrounded answers.

How to read this diagram

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

Step by step
  1. Input guards inspect the request: injection patterns, personal data to redact, topics outside policy.
  2. The request goes to the model only if it passes, possibly redacted.
  3. Output guards inspect the answer: leaked personal data, toxic content, claims not supported by the sources, invalid format.
  4. On failure, the system blocks, redacts, regenerates or escalates to a person.
Key details
  • Combine cheap rules, small classifiers and LLM-based checks.
  • Measure false positives; over-blocking makes people bypass the system.
  • Tool-level policies (approvals, scopes) are guardrails too.
