How does continuous batching work?

In one lineInstead of waiting for a whole batch to finish, the server re-forms the batch at every token step: finished requests leave and waiting ones join immediately.

↻ Re-form the batch at every token step
Step by step
  1. LLM requests vary hugely in output length, from a few tokens to thousands.
  2. With static batching, the GPU waits for the longest request while finished slots stay empty.
  3. Continuous batching schedules at the level of single decode steps.
  4. As soon as a request finishes, a waiting request takes its place in the next step.
Key details
  • Typically gives several times higher throughput than static batching.
  • Standard in vLLM, TGI, TensorRT-LLM and SGLang.

Use it

What you'd write at work

With vLLM you get continuous batching automatically: submit many prompts and it keeps the GPU full. max_num_seqs caps how many run at once.

python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-7B-Instruct", max_num_seqs=256)      # up to 256 requests in flight
prompts = [f"Write {n} words about the sea." for n in (5, 50, 500)] * 100
outputs = llm.generate(prompts, SamplingParams(max_tokens=800))     # short ones finish and free their slot
print(len(outputs), "done;", outputs[0].outputs[0].text[:80])

Checked, not run: needs NVIDIA GPUs and vLLM, which can't be installed on the test machine (a Mac): syntax checked only.

Under the hood

What the library does for you, with its real classes

Real continuous batching on CPU: Hugging Face's generate_batch schedules requests per decode step over a paged KV cache. Requests of very different lengths finish independently.

python
from transformers import AutoModelForCausalLM, AutoTokenizer, GenerationConfig

name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, attn_implementation="sdpa")

questions = ["Say hi.", "Count from 1 to 20.", "Name a colour.", "List five fruits."]   # Step 1: varied lengths
inputs = [tok(tok.apply_chat_template([{"role": "user", "content": q}], add_generation_prompt=True,
                                      tokenize=False)).input_ids for q in questions]

results = model.generate_batch(inputs, generation_config=GenerationConfig(
    max_new_tokens=60, do_sample=False, eos_token_id=tok.eos_token_id), record_timestamps=True)

# Steps 3-4: each request stops on its own; its slot is reused at the next decode step
for (rid, r), q in zip(sorted(results.items()), questions):
    done = r.timestamps[-1] - r.created_time if r.timestamps else 0.0
    print(f"{rid}: {len(r.generated_tokens):2} tokens, finished after {done:4.1f}s  {q!r}")

✓ Ran with transformers 5.24.0.

req_1: 60 tokens, finished after  3.0s  'Count from 1 to 20.'
req_2: 60 tokens, finished after  3.0s  'Name a colour.'
req_3: 29 tokens, finished after  2.4s  'List five fruits.'

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# The same 6 requests (output length in tokens), with 3 batch slots on the GPU.
lengths = {"A": 3, "B": 20, "C": 4, "D": 5, "E": 2, "F": 6}
SLOTS = 3

def static_batching(lengths):
    # Step 2: a batch starts together and ends when its LONGEST request ends
    ids, steps, idle = list(lengths), 0, 0
    for i in range(0, len(ids), SLOTS):
        batch = ids[i:i + SLOTS]
        longest = max(lengths[r] for r in batch)
        steps += longest
        idle += sum(longest - lengths[r] for r in batch)
    return steps, idle

def continuous_batching(lengths):
    # Step 3-4: schedule every decode step; a finished slot is refilled straight away
    waiting, running, steps, finished = list(lengths), {}, 0, {}
    while waiting or running:
        while waiting and len(running) < SLOTS:
            r = waiting.pop(0)
            running[r] = lengths[r]
        steps += 1
        for r in list(running):
            running[r] -= 1
            if running[r] == 0:
                del running[r]
                finished[r] = steps
    return steps, finished

s_steps, s_idle = static_batching(lengths)
c_steps, finished = continuous_batching(lengths)
print(f"static batching:     {s_steps} decode steps, {s_idle} slot-steps wasted waiting")
print(f"continuous batching: {c_steps} decode steps")
print("step at which each request finished:", finished)

✓ Ran with plain Python 3.9+.

What it prints

continuous batching: 20 decode steps

Watch it in a real system
  • vLLM logs a line every few seconds with the number of running and waiting requests: send a burst of requests with very different max_tokens and watch waiting requests join as others finish.
  • Compare throughput (tokens/second) of a naive model.generate() loop over a fixed batch with the same prompts sent to vLLM or TGI.
  • Prometheus metrics such as vllm:num_requests_running and vllm:num_requests_waiting show the same thing on a dashboard.
