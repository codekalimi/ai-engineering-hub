How does an LLM generate text?

In one lineIt predicts one token at a time: text becomes tokens, the transformer scores every possible next token, one is picked, appended, and the loop repeats.

Step by step
  1. The tokenizer splits the text into tokens (sub-word pieces) and maps each one to an integer ID.
  2. Each ID is looked up in an embedding table to get a vector, and position information is added.
  3. The vectors pass through dozens of transformer layers. In each layer, attention mixes in information from earlier tokens, then an MLP transforms it.
  4. The final layer outputs a logit (a score) for every token in the vocabulary, often 100,000+ of them.
  5. Sampling turns the scores into probabilities and picks one token.
  6. That token is appended to the input and the loop runs again. Thanks to the KV cache, each new step only processes the newest token.
Key details
  • Generation is sequential, which is why output length drives latency.
  • The model has no memory between requests: everything it knows about the conversation is in the input tokens.
  • Generation stops at an end-of-sequence token, a stop string, or the max_tokens limit.
Behind the scenes

See it run

A tiny from-scratch version of what really happens. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: plain Python, nothing to install.

python3 · standard library only
# A toy language model: the next-token scores come from a lookup table instead of a transformer.
import math, random
random.seed(0)
VOCAB = ["<eos>", "the", "cat", "sat", "on", "mat", "."]

# Step 1: tokenizer = text -> ids
def encode(text): return [VOCAB.index(w) for w in text.split()]
def decode(ids): return " ".join(VOCAB[i] for i in ids)

# Steps 2-4: the "model" returns one score (logit) per vocabulary token for the NEXT position
BIGRAMS = {"the": {"cat": 1.5, "mat": 3.0}, "cat": {"sat": 3.0}, "sat": {"on": 3.0},
           "on": {"the": 3.0}, "mat": {".": 3.0}, ".": {"<eos>": 5.0}}
def model(ids):
    last = VOCAB[ids[-1]]
    return [BIGRAMS.get(last, {}).get(tok, -2.0) for tok in VOCAB]

# Step 5: sampling turns scores into probabilities and picks one token
def sample(logits, temperature=0.7):
    exps = [math.exp(l / temperature) for l in logits]
    total = sum(exps)
    return random.choices(range(len(VOCAB)), weights=[e / total for e in exps])[0]

# Step 6: the loop - append the new token and run again
ids = encode("the cat")
for step in range(10):                       # max_tokens
    next_id = sample(model(ids))
    print(f"step {step}: {decode(ids)!r:28} -> {VOCAB[next_id]!r}")
    if VOCAB[next_id] == "<eos>":            # stop token
        break
    ids.append(next_id)
print("final:", decode(ids))
What it prints
step 0: 'the cat'                    -> 'sat'
step 1: 'the cat sat'                -> 'on'
step 2: 'the cat sat on'             -> 'the'
step 3: 'the cat sat on the'         -> 'mat'
step 4: 'the cat sat on the mat'     -> '.'
step 5: 'the cat sat on the mat .'   -> '<eos>'
final: the cat sat on the mat .
Watch it in a real system
  • Hugging Face: run the loop yourself: logits = model(input_ids).logits[:, -1, :], pick logits.argmax(), append it to input_ids, repeat. That is exactly what model.generate() does for you.
  • Print the top candidates at each step: model.generate(..., output_scores=True, return_dict_in_generate=True) returns the scores for every generated position.
  • With an API, ask for logprobs=True, top_logprobs=5 (OpenAI-style APIs) to see which tokens the model almost picked.
