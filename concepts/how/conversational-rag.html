How does RAG handle follow-up questions in a chat?

In one lineA follow-up like "what about the second one?" can't be searched as it is, so an LLM first rewrites it into a standalone question using the chat history, and that's what gets retrieved.

Step by step
  1. The user's new message often only makes sense with the earlier turns.
  2. A small, fast model rewrites it into a self-contained question, using the history.
  3. Retrieval runs on the rewritten question.
  4. The final answer is generated from the retrieved context plus the conversation.
Key details
  • Skip the rewrite for the first message of a conversation to save latency.
  • Log the rewritten query; it's a common hidden failure point.
  • Multi-query (several rewrites, results merged) can improve recall further.

Use it

What you'd write at work

Rewrite the follow-up into a standalone question with a fast model, then retrieve with that.

python
from langchain.chat_models import init_chat_model
from langchain.embeddings import init_embeddings
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.vectorstores import InMemoryVectorStore

retriever = InMemoryVectorStore.from_texts(
    ["Contractors are paid monthly via the vendor portal.",
     "Parental leave: 26 weeks paid for employees. Contractors are not eligible."],
    init_embeddings("openai:text-embedding-3-small")).as_retriever(search_kwargs={"k": 1})
fast = init_chat_model("anthropic:claude-haiku-5-5")
main = init_chat_model("anthropic:claude-opus-5-5")

rewrite = ChatPromptTemplate.from_messages([
    MessagesPlaceholder("history"), ("human", "{question}"),
    ("human", "Rewrite my last question as a standalone search query. Reply with the query only."),
]) | fast | StrOutputParser()

history = [("human", "What is our parental leave policy?"), ("ai", "Employees get 26 weeks of paid leave.")]
question = "Does it apply to contractors too?"
query = rewrite.invoke({"history": history, "question": question})
docs = retriever.invoke(query)
print("searched for:", query, "| found:", docs[0].page_content)
print(main.invoke(history + [("system", f"Context: {docs[0].page_content}"), ("human", question)]).content)

✓ Ran with langchain 1.5.2, langchain-core 1.8.4 · with a scripted chat model in place of the API; a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

What it printed
searched for: Does the parental leave policy apply to contractors? | found: Parental leave: 26 weeks paid for employees. Contractors are not eligible.
No - contractors are not eligible for parental leave.

Under the hood

What the library does for you, with its real classes

Why the rewrite matters, shown with the real retriever: the same follow-up, searched raw and rewritten.

python
from langchain.embeddings import init_embeddings
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.vectorstores import InMemoryVectorStore

retriever = InMemoryVectorStore.from_texts(
    ["Contractors are paid monthly via the vendor portal.",
     "Parental leave: 26 weeks paid for employees. Contractors are not eligible."],
    init_embeddings("openai:text-embedding-3-small")).as_retriever(search_kwargs={"k": 1})

history = [("human", "What is our parental leave policy?"), ("ai", "Employees get 26 weeks of paid leave.")]
prompt = ChatPromptTemplate.from_messages([
    MessagesPlaceholder("history"), ("human", "{question}"),
    ("human", "Rewrite my last question as a standalone search query. Reply with the query only."),
])
# Step 2: exactly what the small rewriting model receives
for m in prompt.invoke({"history": history, "question": "Does it apply to contractors too?"}).to_messages():
    print(f"{m.type:5} {m.content}")

# Step 3: retrieval with and without the rewrite
for q in ["Does it apply to contractors too?", "Does the parental leave policy apply to contractors?"]:
    print(f"{q!r:56} -> {retriever.invoke(q)[0].page_content}")

✓ Ran with langchain 1.5.2, langchain-core 1.8.4 · with a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import re
words = lambda t: set(re.findall(r"[a-z]+", t.lower()))

history = [
    ("user", "What is our parental leave policy?"),
    ("assistant", "Employees get 26 weeks of paid parental leave."),
]
follow_up = "Does it apply to contractors too?"
# Step 1: on its own, "it" means nothing to a search engine

# Step 2: a small, fast model rewrites the follow-up into a standalone question
def rewrite(history, question):
    prompt = ("Rewrite the last question so it makes sense without the chat history.\n"
              + "\n".join(f"{role}: {text}" for role, text in history)
              + f"\nuser: {question}\nStandalone question:")
    print("---- rewrite prompt ----\n" + prompt + "\n------------------------")
    return "Does the parental leave policy apply to contractors?"   # what the small LLM returns

standalone = rewrite(history, follow_up)

# Step 3: retrieval runs on the rewritten question
DOCS = ["Contractors are paid monthly via the vendor portal.",
        "Parental leave: 26 weeks paid for employees. Contractors are not eligible."]
best = lambda q: max(DOCS, key=lambda d: len(words(q) & words(d)))
print("search with raw follow-up ->", best(follow_up))
print("search with rewrite       ->", best(standalone))
# Step 4: the answer is generated from the retrieved context plus the conversation

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • LangSmith or set_debug(True): find the rewrite step and read the standalone question it produced; that is what was actually searched.
  • Log both the raw follow-up and the rewritten query for every request, and review the ones with bad answers.
  • Test with pronoun follow-ups ("what about it?", "and for contractors?"): they break retrieval when there is no rewrite step.
