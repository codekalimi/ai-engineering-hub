How does the KV cache work?

In one lineKeys and values for tokens already processed are stored, so each new token only computes its own and reads the rest from the cache.

Step by step
  1. During prefill, the whole prompt is processed in parallel, and every token's keys and values are saved in GPU memory.
  2. During decode, each new token computes only its own query, key and value.
  3. Its query attends over the cached keys and values instead of recomputing the whole prefix.
  4. Its own key and value are appended, so the cache grows by one token per step.
Key details
  • Size ≈ 2 × layers × KV heads × head dim × bytes × tokens: about 0.3 MB per token for a 70B GQA model in FP16.
  • The cache, not the weights, usually limits how many requests fit on a GPU at once.
  • Prompt (prefix) caching reuses the cached keys and values of an identical prefix across requests.
