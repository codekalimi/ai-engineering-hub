How do reasoning (thinking) models work?

In one lineThey're trained to write out intermediate reasoning before the final answer. Spending more tokens on thinking lets them solve harder multi-step problems.

↻ A bigger thinking budget allows more attempts and self-checks
Step by step
  1. The model first generates a chain of reasoning (often hidden or summarized): breaking the problem down, trying approaches, checking results.
  2. This behaviour is trained with reinforcement learning on tasks with verifiable answers, like maths and code, so reasoning that leads to correct answers gets rewarded.
  3. Only after thinking does it write the answer the user sees.
  4. Many APIs expose a thinking budget or effort level to trade quality against latency and cost.
Key details
  • Thinking tokens are usually billed as output tokens.
  • The biggest gains are on maths, coding, planning and complex analysis; they're small on simple lookups.
  • Prompting "think step by step" matters far less with these models.

Use it

What you'd write at work

Thinking is adaptive on current Claude models: you choose how hard it works with effort. Server-side fallback reruns the request on another model if this one declines.

python
import anthropic

client = anthropic.Anthropic()
response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    thinking={"type": "adaptive", "display": "summarized"},   # show a summary of the reasoning
    output_config={"effort": "high"},                          # low | medium | high | xhigh | max
    betas=["server-side-fallback-2026-07-01"],
    fallbacks="default",                                        # rerun on a fallback model if declined
    messages=[{"role": "user", "content": "Is 1001 a prime number?"}],
)
for block in response.content:
    if block.type == "thinking":
        print("THINKING:", block.thinking)
    elif block.type == "text":
        print("ANSWER:  ", block.text)
print("output tokens (thinking included):", response.usage.output_tokens)

✓ Ran with anthropic 2.13.0 · with a mocked Anthropic HTTP endpoint (the real SDK validated the request).

What it printed
THINKING: 1001 is odd and its digit sum is 2, so not 3. Try 7: 7 x 143 = 1001. And 143 = 11 x 13.
ANSWER:   No. 1001 = 7 x 11 x 13.
output tokens (thinking included): 140

Under the hood

What the library does for you, with its real classes

How the habit of reasoning is trained (Step 2): sample several chains, score them with a checker, push up the ones that beat the group average. This is the core of GRPO, as in TRL's GRPOTrainer.

python
import torch

question = "What is 17 x 24?"
answers = ["408", "398", "408", "418", "408", "408"]   # final answers of 6 sampled reasoning chains
correct = "408"                                        # verifiable: code can check it

rewards = torch.tensor([1.0 if a == correct else 0.0 for a in answers])
advantages = (rewards - rewards.mean()) / (rewards.std() + 1e-6)   # better than the group -> positive
print("rewards:   ", rewards.tolist())
print("advantages:", [round(a, 2) for a in advantages.tolist()])

# log-probability the model gave each whole chain (normally summed over its tokens)
logprobs = torch.tensor([-42.0, -40.0, -45.0, -39.0, -44.0, -41.0], requires_grad=True)
loss = -(advantages * logprobs).mean()        # policy gradient
loss.backward()
step = (-logprobs.grad).tolist()              # gradient descent moves log-probs this way
print("push each chain:", ["up" if s > 0 else "down" for s in step])

✓ Ran with torch 2.15.0.

What it printed
rewards:    [1.0, 0.0, 1.0, 0.0, 1.0, 1.0]
advantages: [0.65, -1.29, 0.65, -1.29, 0.65, 0.65]
push each chain: ['up', 'down', 'up', 'down', 'up', 'up']

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Thinking = writing intermediate steps before answering. RL rewards chains that reach right answers.
import random
random.seed(3)

def think_and_answer(a, b, budget, slip=0.15):
    # computes a x b via partial products; each written step may contain a small slip
    tens, ones = b // 10 * 10, b % 10
    steps = [(f"{a} x {tens}", a * tens), (f"{a} x {ones}", a * ones)]
    thoughts, total = [], 0
    for i, (text, value) in enumerate(steps):
        if i >= budget:                          # out of thinking budget: guess
            value = a * b // 20 * 10
            text += " (guessed)"
        elif random.random() < slip:
            value += random.choice([-10, 10])    # an arithmetic slip
        thoughts.append(f"{text} = {value}")
        total += value
    return thoughts, total

# Step 1 + 3: think first (often hidden), then answer. Step 4: the budget trades cost for quality
for budget in (0, 2):
    thoughts, answer = think_and_answer(17, 24, budget)
    print(f"budget {budget}: thinking {thoughts} -> answer {answer}")

# Step 2: RL with a verifiable reward - sample many chains, reward the ones that are right
correct = 17 * 24
samples = [think_and_answer(17, 24, 2) for _ in range(8)]
rewards = [1 if ans == correct else 0 for _, ans in samples]
print("rewards for 8 sampled chains:", rewards)
print("training raises the probability of the rewarded chains, so careful reasoning becomes the habit")

✓ Ran with plain Python 3.9+.

What it prints

budget 2: thinking ['17 x 20 = 340', '17 x 4 = 68'] -> answer 408
rewards for 8 sampled chains: [1, 0, 1, 1, 1, 1, 1, 1]

Watch it in a real system
  • Anthropic API: current Claude models think adaptively; send thinking={"type": "adaptive", "display": "summarized"} and set depth with output_config={"effort": "high"}. The response has thinking blocks before the text block. (The older fixed budget_tokens setting is rejected by current models.)
  • OpenAI-style APIs report hidden reasoning in usage, e.g. usage.completion_tokens_details.reasoning_tokens: compare it with the visible answer length.
  • Run one hard question at low and high effort/budget and compare accuracy, latency and tokens.
