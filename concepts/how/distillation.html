How does distillation work?

In one lineA large "teacher" model generates high-quality outputs, and a smaller "student" model is fine-tuned on them, inheriting much of the teacher's ability on that task at a fraction of the cost.

Step by step
  1. Collect realistic prompts for the task you care about.
  2. Run them through a large, capable teacher model.
  3. Filter the outputs for quality (automatic checks or review).
  4. Fine-tune a smaller student model on the teacher's outputs.
  5. Evaluate the student against the teacher on held-out examples.
Key details
  • Works best for narrow, high-volume tasks.
  • Check the teacher provider's terms; some restrict training other models on outputs.

Use it

What you'd write at work

Build the distillation dataset: run real prompts through the teacher (with structured output so labels are clean), filter, save JSONL for fine-tuning a smaller model.

python
import json
from typing import Literal

from pydantic import BaseModel
from langchain.chat_models import init_chat_model

class Label(BaseModel):
    category: Literal["billing", "technical"]
    confident: bool

teacher = init_chat_model("anthropic:claude-opus-5-5").with_structured_output(Label)   # Step 2
prompts = ["I was charged twice", "The app crashes on login", "Something is wrong with my plan"]  # Step 1

with open("distill.jsonl", "w") as f:
    for p in prompts:
        label = teacher.invoke(f"Classify this support ticket: {p}")
        if not label.confident:                                    # Step 3: drop doubtful labels
            print("skipped:", p)
            continue
        f.write(json.dumps({"messages": [{"role": "user", "content": p},
                                         {"role": "assistant", "content": label.category}]}) + "\n")
print(open("distill.jsonl").read())
# Step 4: fine-tune a small model on distill.jsonl (see the SFT page); Step 5: evaluate both on held-out data

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

Under the hood

What the library does for you, with its real classes

Soft-label distillation, when you can see the teacher's probabilities: the student matches the teacher's whole distribution (temperature-softened), not just its top answer.

python
import torch
import torch.nn.functional as F

torch.manual_seed(0)
classes = ["billing", "technical", "account", "other"]
teacher_logits = torch.tensor([[4.0, 1.5, 2.5, -1.0]])          # teacher: billing, but account is close
student_logits = torch.zeros(1, 4, requires_grad=True)           # student starts knowing nothing
opt = torch.optim.SGD([student_logits], lr=1.0)
T = 2.0                                                          # temperature softens both distributions

for step in range(1, 6):
    soft_targets = F.softmax(teacher_logits / T, dim=-1)
    loss = F.kl_div(F.log_softmax(student_logits / T, dim=-1), soft_targets, reduction="batchmean") * T * T
    opt.zero_grad()
    loss.backward()
    opt.step()
    print(f"step {step}: KL loss {loss.item():.3f}")

def show(logits):
    return {c: round(p, 2) for c, p in zip(classes, F.softmax(logits, -1)[0].tolist())}
print("teacher:", show(teacher_logits))
print("student:", show(student_logits.detach()))     # learns the ranking, including "account is close"

✓ Ran with torch 2.15.0.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Step 1: realistic prompts for the task (classifying support tickets)
prompts = ["refund not received", "app crashes on login", "charged twice", "cannot reset password",
           "invoice missing", "screen freezes", "card declined", "login code never arrives"]

def teacher(p):
    # Step 2: the big, expensive model labels them (stubbed)
    return "billing" if any(w in p for w in ["refund", "charged", "invoice", "card"]) else "technical"

data = [(p, teacher(p)) for p in prompts]
data = [(p, y) for p, y in data if y in {"billing", "technical"}]     # Step 3: quality filter

# Step 4: "fine-tune" a tiny student: learn which words point to which label
weights = {}
for p, y in data:
    for w in p.split():
        weights.setdefault(w, {"billing": 0, "technical": 0})[y] += 1

def student(p):
    votes = {"billing": 0, "technical": 0}
    for w in p.split():
        for label, n in weights.get(w, {}).items():
            votes[label] += n
    return max(votes, key=votes.get)

# Step 5: compare the student with the teacher on NEW examples
test = ["refund still pending", "crashes after update", "charged for a cancelled plan", "password email not arriving"]
for p in test:
    print(f"{p!r:32} teacher={teacher(p):9} student={student(p)}")
agree = sum(student(p) == teacher(p) for p in test)
print(f"student agrees with the teacher on {agree}/{len(test)} - at a fraction of the cost per request")

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • Keep the teacher’s outputs as a dataset (JSONL of prompt and response) and read a sample by hand before training: the student copies mistakes too.
  • Evaluate teacher and student on the same held-out set and report both quality and cost/latency per request: that ratio is the business case.
  • Check the teacher provider’s terms: some forbid using outputs to train competing models.
