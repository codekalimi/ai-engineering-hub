How does an LCEL chain (prompt | model | parser) execute?

In one lineThe | operator only builds a RunnableSequence object. When you call invoke, it runs each step in order, passing each output into the next step.

How to read this diagram

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

Step by step
  1. Every component implements the Runnable interface: invoke, batch, stream and their async versions.
  2. a | b calls a.__or__(b), which returns a RunnableSequence. A dict becomes a RunnableParallel and a function becomes a RunnableLambda.
  3. invoke loops over the steps, feeding each output into the next step's input.
  4. stream passes chunks through every step that supports streaming, so tokens reach you as they're generated.
  5. batch runs many inputs in parallel with a thread pool (or asyncio for abatch).
Key details
  • The config (callbacks, tags, run name) is passed down to every inner step, which is how tracing sees each one.
  • A plain function in the middle of a chain stops streaming at that point unless it's a generator.
chain = prompt | model | StrOutputParser()

# what invoke does, conceptually:
def invoke(x):
    for step in [prompt, model, parser]:
        x = step.invoke(x)
    return x
