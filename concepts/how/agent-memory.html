How does agent memory work (short-term vs long-term)?

In one lineShort-term memory is the current conversation's state, saved per thread. Long-term memory is facts saved across conversations, searched and added to the prompt when relevant.

Step by step
  1. Short-term memory is the message history and working state of one conversation, checkpointed per thread_id so it can resume.
  2. Long-term memory stores durable facts, such as preferences or past decisions, in a store organized by namespace (e.g. per user).
  3. Memories are written either by the agent as it works (a "save memory" tool) or by a background job afterwards.
  4. In a later conversation, relevant memories are searched and added to the prompt.
Key details
  • Trim or summarize short-term history to control token cost.
  • Be deliberate about what's saved long-term, to avoid storing noise or sensitive data.
  • Let users see and delete what's remembered about them.

Use it

What you'd write at work

Short-term memory = a checkpointer (per thread). Long-term memory = a store (per user), reached from tools through the runtime.

python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import ToolRuntime, tool
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.store.memory import InMemoryStore

@tool
def save_memory(fact: str, runtime: ToolRuntime) -> str:
    """Save a lasting fact about the user."""
    runtime.store.put(("memories", "user-42"), fact, {"fact": fact})
    return "saved"

@tool
def recall(query: str, runtime: ToolRuntime) -> str:
    """Look up what we know about the user."""
    return str([item.value["fact"] for item in runtime.store.search(("memories", "user-42"))])

agent = create_agent(init_chat_model("anthropic:claude-opus-5-5"), [save_memory, recall],
                     checkpointer=InMemorySaver(),        # short-term: per thread
                     store=InMemoryStore())                # long-term: across threads

def chat(thread, text):
    out = agent.invoke({"messages": [("user", text)]}, {"configurable": {"thread_id": thread}})
    print(f"[{thread}] {text!r} -> {out['messages'][-1].content}  ({len(out['messages'])} messages in thread)")

chat("thread-1", "I'm vegetarian. Remember that.")
chat("thread-2", "Suggest a dinner place near my hotel.")    # new thread: no history, but the memory is there

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API.

What it printed
[thread-1] "I'm vegetarian. Remember that." -> Noted - I'll keep dinner suggestions vegetarian.  (4 messages in thread)
[thread-2] 'Suggest a dinner place near my hotel.' -> Since you're vegetarian, try Green Leaf near your hotel.  (4 messages in thread)

Under the hood

What the library does for you, with its real classes

The two memories as objects you can query: the checkpointer's per-thread state, and a store with semantic search over memories.

python
from langchain.chat_models import init_chat_model
from langchain.embeddings import init_embeddings
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import START, MessagesState, StateGraph
from langgraph.store.memory import InMemoryStore

# Short-term (Step 1): a checkpointer keeps each thread's messages
model = init_chat_model("anthropic:claude-opus-5-5")
graph = StateGraph(MessagesState)
graph.add_node("chat", lambda s: {"messages": [model.invoke(s["messages"])]})
graph.add_edge(START, "chat")
app = graph.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "thread-1"}}
app.invoke({"messages": [("user", "hi")]}, cfg)
app.invoke({"messages": [("user", "hi again")]}, cfg)
print("thread-1 holds", len(app.get_state(cfg).values["messages"]), "messages")
print("thread-2 holds", len(app.get_state({"configurable": {"thread_id": "thread-2"}}).values.get("messages", [])))

# Long-term (Steps 2-4): a store, namespaced per user, with semantic search
store = InMemoryStore(index={"embed": init_embeddings("openai:text-embedding-3-small"), "dims": 384})
ns = ("memories", "user-42")
for key, fact in [("diet", "User is vegetarian"), ("seat", "Prefers an aisle seat on flights"),
                  ("lang", "Writes in British English")]:
    store.put(ns, key, {"text": fact})
for item in store.search(ns, query="what food should I suggest?", limit=2):
    print(f"{item.score:.2f}  {item.value['text']}")

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API; a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

What it printed
thread-1 holds 4 messages
thread-2 holds 0
0.21  User is vegetarian
0.12  Prefers an aisle seat on flights

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import json, re
words = lambda t: set(re.findall(r"[a-z]+", t.lower()))

threads = {}   # short-term: each conversation's messages, saved per thread (a checkpointer does this)
store = {}     # long-term: durable facts per user, searchable across conversations (a store does this)

def save_memory(user, fact):
    # Step 3: written by the agent through a "save memory" tool (or by a background job)
    store.setdefault(user, []).append(fact)

def search_memory(user, query):
    # Step 4: in a later conversation, find relevant memories (real stores use embeddings)
    return [f for f in store.get(user, []) if words(f) & words(query)]

def chat(user, thread, message):
    history = threads.setdefault(thread, [])        # Step 1: load this thread's history
    memories = search_memory(user, message)         # Step 2/4: plus relevant long-term facts
    print(f"[{thread}] {message!r}")
    print(f"   prompt = {len(history)} earlier messages + memories {memories}")
    history += [("user", message), ("assistant", "...")]
    if "I'm vegetarian" in message:
        save_memory(user, "User is vegetarian")
    if "aisle" in message:
        save_memory(user, "User prefers an aisle seat on flights")

chat("user-42", "thread-1", "I'm vegetarian, plan a dinner for Friday")
chat("user-42", "thread-1", "Also I like an aisle seat when I fly")
# A brand-new conversation: no history, but the long-term memory comes back
chat("user-42", "thread-2", "Find a vegetarian place near my hotel")
print("long-term store:", json.dumps(store))

✓ Ran with plain Python 3.9+.

What it prints
[thread-1] "I'm vegetarian, plan a dinner for Friday"
   prompt = 0 earlier messages + memories []
[thread-1] 'Also I like an aisle seat when I fly'
   prompt = 2 earlier messages + memories []
[thread-2] 'Find a vegetarian place near my hotel'
   prompt = 0 earlier messages + memories ['User is vegetarian']
long-term store: {"user-42": ["User is vegetarian", "User prefers an aisle seat on flights"]}
Watch it in a real system
  • LangGraph short-term memory: graph.get_state({"configurable": {"thread_id": "t1"}}).values["messages"] shows exactly what the next turn will see.
  • LangGraph long-term memory: store.search(("memories", user_id), query="food preferences") returns stored items with similarity scores; print them before they go into the prompt.
  • Print the final prompt of a new conversation to check that the right memories (and only those) were injected.
