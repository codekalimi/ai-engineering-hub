How does prompt injection happen, and how do you defend against it?

In one lineInstructions hidden in content the model reads (a web page, email or document) can hijack it. Defence is layered: limit what the model can do, and check its actions in code.

Step by step
  1. The agent is asked to do something ordinary, like summarize a page or an inbox.
  2. The content contains text written to look like instructions.
  3. The model can't reliably tell data from instructions, so it may follow them.
  4. If it has a powerful tool, the injected instruction turns into a real action.
  5. Defence: give tools least privilege, check every action in code, require approval for risky actions, and filter outputs (e.g. block unexpected links).
Key details
  • No prompt wording fully prevents injection; the real protection is limiting what the model can do.
  • Run agents with the user's own permissions (delegated OAuth), never as a super-user.
  • Keep injection test cases in your eval set.
