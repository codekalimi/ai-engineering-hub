How does a vector database find nearest neighbours fast (HNSW)?

In one lineInstead of comparing the query with every vector, it walks a layered graph of neighbour links: long jumps on sparse upper layers, then finer steps on denser lower layers.

↻ Repeat the greedy search on each layer down to the bottom
Step by step
  1. When a vector is inserted, it's linked to its nearest neighbours; a few vectors are also placed on higher, sparser layers.
  2. A search starts at an entry point on the top layer and keeps moving to whichever neighbour is closer to the query.
  3. When no neighbour is closer, it drops to the next layer and continues from that point.
  4. On the bottom layer, it explores a list of candidates (size ef) and returns the best k.
Key details
  • It's approximate: very fast, with recall usually 95–99%+, tunable through the M and ef parameters.
  • Exact brute-force search is fine up to tens of thousands of vectors.
  • Other index types: IVF (cluster first, then search nearby clusters), often combined with product quantization to compress vectors.

Use it

What you'd write at work

An HNSW index trades a little recall for a lot of speed; efSearch is the dial. pgvector equivalent: CREATE INDEX ... USING hnsw (embedding vector_cosine_ops); SET hnsw.ef_search = 100;

python
import time
import faiss
import numpy as np

rng = np.random.default_rng(0)
d = 64
data = rng.random((20000, d), dtype=np.float32)
queries = rng.random((200, d), dtype=np.float32)

index = faiss.IndexHNSWFlat(d, 32)           # M = 32 links per vector
index.add(data)
exact = faiss.IndexFlatL2(d)                 # brute force, for the true answers
exact.add(data)
_, truth = exact.search(queries, 10)

for ef in (8, 32, 128):
    index.hnsw.efSearch = ef                 # size of the candidate list at query time
    start = time.time()
    _, found = index.search(queries, 10)
    ms = (time.time() - start) * 1000
    recall = np.mean([len(set(f) & set(t)) / 10 for f, t in zip(found, truth)])
    print(f"efSearch={ef:3}: recall@10 {recall:.2f} in {ms:.0f} ms for {len(queries)} queries")

✓ Ran with faiss-cpu 1.16.0, numpy 2.5.5.

What it printed

efSearch= 32: recall@10 0.74 in 1 ms for 200 queries
efSearch=128: recall@10 0.97 in 3 ms for 200 queries

Under the hood

What the library does for you, with its real classes

Inside the index FAISS built: why the upper layers are sparse. Each vector draws its top layer at random, so each layer has about 1/M of the vectors of the one below.

python
import faiss
import numpy as np

rng = np.random.default_rng(0)
d, M, n = 64, 32, 20000
index = faiss.IndexHNSWFlat(d, M)
index.add(rng.random((n, d), dtype=np.float32))

levels = faiss.vector_to_array(index.hnsw.levels)      # per vector: how many layers it lives on
print("top layer:", index.hnsw.max_level, "| search starts at vector", index.hnsw.entry_point)
for layer in range(levels.max() - 1, -1, -1):
    print(f"layer {layer}: {(levels > layer).sum():6} vectors")

# Step 1: the level draw used on insert: floor(-ln(U) * mL), with mL = 1 / ln(M)
mL = 1 / np.log(M)
drawn = np.floor(-np.log(rng.random(n)) * mL)
print("same rule, simulated:", [int((drawn >= layer).sum()) for layer in range(int(drawn.max()), -1, -1)])
# Steps 2-4 (greedy descent, then a beam of size efSearch on layer 0) run inside index.search()

✓ Ran with faiss-cpu 1.16.0, numpy 2.5.5.

layer 2:     14 vectors

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# A small HNSW-style search: a sparse top layer for long jumps, a dense bottom layer for precision.
import math, random
random.seed(7)

points = [(random.uniform(0, 100), random.uniform(0, 100)) for _ in range(400)]
query = (73.0, 21.0)

# Step 1 (insert): link every point to its nearest neighbours; a few points are also promoted
# to an upper layer. (Real HNSW builds this incrementally as vectors arrive.)
def link(ids, m):
    return {i: sorted((j for j in ids if j != i), key=lambda j: math.dist(points[i], points[j]))[:m] for i in ids}
bottom_ids = list(range(len(points)))
top_ids = bottom_ids[::20]                     # ~5% of the points
layers = [link(top_ids, 4), link(bottom_ids, 8)]

memo = {}                                      # count how many distances we compute
def d(i):
    if i not in memo:
        memo[i] = math.dist(points[i], query)
    return memo[i]

# Steps 2-3: greedy walk on the top layer, then drop down and continue from there
cur = top_ids[0]
for name, graph in zip(["top", "bottom"], layers):
    improved = True
    while improved:
        improved = False
        for n in graph[cur]:
            if d(n) < d(cur):
                cur, improved = n, True
    print(f"{name:6} layer: closest so far = point {cur} at distance {d(cur):.1f}")

# Step 4: on the bottom layer, explore a candidate list of size ef and keep the best k
ef, k = 16, 3
cands, seen, frontier = [cur], {cur}, [cur]
while frontier:
    for n in layers[1][frontier.pop()]:
        if n not in seen:
            seen.add(n)
            cands = sorted(cands + [n], key=d)[:ef]
            if n in cands:
                frontier.append(n)

exact = sorted(bottom_ids, key=lambda i: math.dist(points[i], query))[:k]
print("HNSW top-3: ", sorted(cands, key=d)[:k], f"({len(memo)} distance checks)")
print("exact top-3:", exact, f"({len(points)} distance checks)")

✓ Ran with plain Python 3.9+.
