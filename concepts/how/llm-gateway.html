How does an LLM gateway handle a request?

In one lineEvery app calls one internal API; the gateway authenticates the team, enforces limits, checks the cache, routes to the right model, falls back on errors and records usage.

Step by step
  1. Apps call the gateway with a model alias instead of a specific provider and model.
  2. The gateway authenticates the team and checks its rate limits and budget.
  3. It can return a cached response for repeated requests.
  4. It maps the alias to a provider and model, and calls it.
  5. On errors or timeouts it retries or falls back to another provider.
  6. It records tokens, cost, latency and team for every request.
Key details
  • Model upgrades become one central change behind an eval gate.
  • A natural place for PII redaction, logging policy and guardrails.
  • It's on every request's path, so it must be highly available and add little latency.

Use it

What you'd write at work

Gateway features you can get inside the app with LangChain: retries, fallback to another model, a response cache and a rate limiter. A shared gateway service (e.g. LiteLLM proxy) does the same for every team.

python
from langchain.chat_models import init_chat_model
from langchain_core.caches import InMemoryCache
from langchain_core.globals import set_llm_cache
from langchain_core.rate_limiters import InMemoryRateLimiter

set_llm_cache(InMemoryCache())                                       # identical requests are served from cache
limiter = InMemoryRateLimiter(requests_per_second=5, max_bucket_size=10)

primary = init_chat_model("anthropic:claude-opus-5-5", rate_limiter=limiter)
backup = init_chat_model("anthropic:claude-sonnet-5-5", rate_limiter=limiter)
model = primary.with_fallbacks([backup])                             # on an error, try the next model

print(model.invoke("Where is my order #123?").content)               # primary fails -> backup answers
print(model.invoke("Where is my order #123?").content, "(second call: from cache)")

✓ Ran with langchain 1.5.2, langchain-core 1.8.4 · with a scripted chat model in place of the API.

What it printed
Your order ships tomorrow.
Your order ships tomorrow. (second call: from cache)

Under the hood

What the library does for you, with its real classes

A minimal gateway service: one endpoint, model aliases, a per-team budget, fallback and a usage log. Tested with FastAPI's test client.

python
from fastapi import FastAPI, HTTPException
from fastapi.testclient import TestClient
from pydantic import BaseModel

ALIASES = {"smart": ["provider-a/big-model", "provider-b/big-model-2"]}   # primary, then fallback
BUDGET_USD = {"team-search": 0.001}
SPENT, USAGE_LOG = {}, []

def call_provider(target, prompt):                       # stands in for the provider SDK calls
    if target.startswith("provider-a"):
        raise TimeoutError("provider-a timed out")
    return f"[{target}] answer to {prompt!r}", 120

class ChatRequest(BaseModel):
    model: str
    prompt: str

app = FastAPI()

@app.post("/v1/chat")
def chat(req: ChatRequest, team: str = "team-search"):
    if SPENT.get(team, 0) >= BUDGET_USD[team]:                       # Step 2: budget check
        raise HTTPException(429, "budget exceeded")
    for target in ALIASES[req.model]:                                # Step 4: alias -> real model
        try:
            text, tokens = call_provider(target, req.prompt)
        except TimeoutError:
            continue                                                 # Step 5: fall back
        SPENT[team] = SPENT.get(team, 0) + tokens * 5 / 1e6
        USAGE_LOG.append({"team": team, "model": target, "tokens": tokens})   # Step 6: record usage
        return {"model": target, "text": text}
    raise HTTPException(503, "all providers failed")

client = TestClient(app)
for _ in range(3):
    r = client.post("/v1/chat", json={"model": "smart", "prompt": "hi"})
    print(r.status_code, r.json())
print("usage log:", USAGE_LOG)

✓ Ran with Python 3.12.14.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import random
random.seed(1)

ALIASES = {"smart": [("provider-a", "big-model"), ("provider-b", "big-model-2")]}   # primary, fallback
BUDGET, SPENT = {"team-search": 1.00}, {"team-search": 0.0}
CACHE, LOG = {}, []

def call_provider(provider, model, prompt):
    if provider == "provider-a" and random.random() < 0.7:
        raise TimeoutError(f"{provider} timed out")
    return f"[{model}] answer to {prompt!r}", 120             # text, tokens

def gateway(team, alias, prompt):
    # Step 1: the app asked for an alias, not a provider. Step 2: auth, rate limit, budget
    if SPENT[team] >= BUDGET[team]:
        return "429 budget exceeded"
    # Step 3: cached response for an identical request
    if (alias, prompt) in CACHE:
        LOG.append((team, "cache", 0))
        return CACHE[alias, prompt] + " (from cache)"
    # Step 4-5: map the alias to provider/model; on errors fall back to the next one
    for provider, model in ALIASES[alias]:
        try:
            text, tokens = call_provider(provider, model, prompt)
        except TimeoutError as err:
            print(f"   {err}, falling back")
            continue
        SPENT[team] += tokens * 2 / 1e6
        LOG.append((team, provider, tokens))                   # Step 6: record usage per team
        CACHE[alias, prompt] = text
        return text
    return "503 all providers failed"

for prompt in ["summarize ticket 1", "summarize ticket 1", "summarize ticket 2"]:
    print(gateway("team-search", "smart", prompt))
print("usage log:", LOG)

✓ Ran with plain Python 3.9+.
