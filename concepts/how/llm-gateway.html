How does an LLM gateway handle a request?

In one lineEvery app calls one internal API; the gateway authenticates the team, enforces limits, checks the cache, routes to the right model, falls back on errors and records usage.

How to read this diagram

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

Step by step
  1. Apps call the gateway with a model alias instead of a specific provider and model.
  2. The gateway authenticates the team and checks its rate limits and budget.
  3. It can return a cached response for repeated requests.
  4. It maps the alias to a provider and model, and calls it.
  5. On errors or timeouts it retries or falls back to another provider.
  6. It records tokens, cost, latency and team for every request.
Key details
  • Model upgrades become one central change behind an eval gate.
  • A natural place for PII redaction, logging policy and guardrails.
  • It's on every request's path, so it must be highly available and add little latency.
