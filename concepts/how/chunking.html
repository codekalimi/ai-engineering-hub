How does recursive text splitting work?

In one lineIt splits on the biggest natural boundary first (paragraphs) and only falls back to smaller ones (lines, words, characters) for pieces that are still too big, then adds overlap.

Step by step
  1. The splitter has an ordered list of separators: by default paragraph break, line break, space, then single characters.
  2. It splits on the first separator and checks the size of each piece.
  3. Pieces that are still too large are split again with the next separator.
  4. Small neighbouring pieces are merged back together up to chunk_size, so chunks aren't tiny.
  5. Each chunk repeats the end of the previous one (overlap), so an idea crossing a boundary isn't lost.
Key details
  • Sizes are in characters unless you use a token-based length function.
  • Structure-aware splitters (markdown headings, code syntax) often do better.
  • Store the chunk's position and parent document ID, for citations and for expanding context later.
