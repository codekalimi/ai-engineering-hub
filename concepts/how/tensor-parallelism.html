How does tensor parallelism split a model across GPUs?

In one lineEach layer's weight matrices are split across GPUs; every GPU computes its slice in parallel, and the partial results are combined over a fast link before the next layer.

Step by step
  1. A layer's weight matrix is split into slices, one per GPU.
  2. Each GPU multiplies the same input by its own slice.
  3. The partial results are combined (all-gather or all-reduce) over NVLink.
  4. This happens in every layer, so the GPUs communicate constantly.
Key details
  • Use it when the model doesn't fit on one GPU or you need lower latency.
  • It needs very fast interconnect, so it's usually kept within one node.
  • Pipeline parallelism (layers on different GPUs) is used across nodes instead.

Use it

What you'd write at work

Split a model too big for one GPU across several in the same node. One argument (or --tensor-parallel-size on the CLI).

python
from vllm import LLM, SamplingParams

llm = LLM(model="Qwen/Qwen2.5-72B-Instruct", tensor_parallel_size=4)   # 4 GPUs in one NVLink node
print(llm.generate(["Hello"], SamplingParams(max_tokens=20))[0].outputs[0].text)
# Across nodes, combine with pipeline parallelism: pipeline_parallel_size=2

Checked, not run: needs NVIDIA GPUs and vLLM, which can't be installed on the test machine (a Mac): syntax checked only.

Under the hood

What the library does for you, with its real classes

Tensor parallelism with real collectives: two processes (CPU stand-ins for GPUs) each hold half of a layer's weights, compute their slice, and all-gather. The gloo backend plays the role NCCL plays on GPUs.

python
import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp

def worker(rank, world_size, W, x):
    os.environ.update(MASTER_ADDR="127.0.0.1", MASTER_PORT="29511")
    dist.init_process_group("gloo", rank=rank, world_size=world_size)
    shard = W.chunk(world_size, dim=0)[rank]                # Step 1: this GPU's rows of the weight
    partial = x @ shard.T                                   # Step 2: same input, own slice
    pieces = [torch.empty_like(partial) for _ in range(world_size)]
    dist.all_gather(pieces, partial)                        # Step 3: exchange the slices
    full = torch.cat(pieces, dim=-1)
    if rank == 0:
        print(f"rank 0 holds {tuple(shard.shape)} of {tuple(W.shape)} weights")
        print("all-gathered output equals single-device result:", torch.allclose(full, x @ W.T, atol=1e-6))
    dist.destroy_process_group()

if __name__ == "__main__":
    torch.manual_seed(0)
    W, x = torch.randn(8, 6), torch.randn(2, 6)
    mp.spawn(worker, args=(2, W, x), nprocs=2)              # Step 4: every layer does this, every token

✓ Ran with torch 2.15.0.

What it printed
rank 0 holds (4, 6) of (8, 6) weights
all-gathered output equals single-device result: True

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# y = W x for one layer, computed on 1 GPU, then split across 2 "GPUs".
W = [[1, 2, 0, 1],
     [0, 1, 3, 1],
     [2, 0, 1, 0],
     [1, 1, 1, 1]]
x = [1, 2, 3, 4]
matvec = lambda M, v: [sum(a * b for a, b in zip(row, v)) for row in M]
print("single GPU:      ", matvec(W, x))

# Step 1: split the weight matrix, one slice per GPU (here: by output rows)
gpu0, gpu1 = W[:2], W[2:]
# Step 2: every GPU multiplies the SAME input by its own slice
part0, part1 = matvec(gpu0, x), matvec(gpu1, x)
print("gpu0:", part0, " gpu1:", part1)
# Step 3: all-gather the pieces over NVLink so every GPU has the full output
print("all-gather:      ", part0 + part1)

# The other split: by input columns. Each GPU gets a PARTIAL SUM, combined with an all-reduce (add).
W0, W1 = [row[:2] for row in W], [row[2:] for row in W]
p0, p1 = matvec(W0, x[:2]), matvec(W1, x[2:])
print("partial sums:", p0, p1, "-> all-reduce:", [a + b for a, b in zip(p0, p1)])
# Step 4: this happens in every layer, so GPUs talk constantly - keep tensor parallelism inside one node

✓ Ran with plain Python 3.9+.

What it prints
single GPU:       [9, 15, 5, 10]
gpu0: [9, 15]  gpu1: [5, 10]
all-gather:       [9, 15, 5, 10]
partial sums: [5, 2, 2, 3] [4, 13, 3, 7] -> all-reduce: [9, 15, 5, 10]
Watch it in a real system
  • vLLM: vllm serve <model> --tensor-parallel-size 2, then nvidia-smi shows the weights split across both GPUs, each using about half the weight memory.
  • nvidia-smi topo -m shows how GPUs are connected (NVLink vs PCIe); tensor parallelism needs the fast links.
  • Set NCCL_DEBUG=INFO to see the communication library set up the all-reduce/all-gather channels at startup.
