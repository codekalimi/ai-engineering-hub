How does a checkpointer let a graph remember and resume?

In one lineAfter every step, the graph's state is saved under the thread_id. Calling the graph again with the same thread_id loads the latest state and carries on from there.

Step by step
  1. The checkpointer is passed at compile time: graph.compile(checkpointer=...).
  2. Every invoke includes config={"configurable": {"thread_id": ...}}.
  3. After each step, a snapshot of the state is written for that thread.
  4. On the next invoke with the same thread_id, the latest snapshot is loaded, so a chat remembers earlier messages and a paused run resumes.
  5. get_state_history lists all snapshots, so you can inspect or resume from an older one (time travel).
Key details
  • InMemorySaver for development; SqliteSaver or PostgresSaver for anything real.
  • One thread_id per conversation. Reusing one across users mixes their histories.

Use it

What you'd write at work

Compile with a checkpointer and pass a thread_id: each thread remembers its own conversation.

python
from langchain.chat_models import init_chat_model
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import START, MessagesState, StateGraph

model = init_chat_model("anthropic:claude-opus-5-5")
graph = StateGraph(MessagesState)
graph.add_node("chat", lambda state: {"messages": [model.invoke(state["messages"])]})
graph.add_edge(START, "chat")
app = graph.compile(checkpointer=InMemorySaver())   # in production: a Postgres or SQLite checkpointer

def say(thread, text):
    out = app.invoke({"messages": [("user", text)]}, {"configurable": {"thread_id": thread}})
    print(f"[{thread}] {text} -> {out['messages'][-1].content}")

say("asha", "Hi, I'm Asha.")
say("asha", "What's my name?")          # same thread: the history is loaded
say("bob", "What's my name?")           # different thread: empty history

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API.

What it printed
[asha] Hi, I'm Asha. -> Nice to meet you, Asha!
[asha] What's my name? -> Your name is Asha.
[bob] What's my name? -> I don't know your name yet.

Under the hood

What the library does for you, with its real classes

The snapshots themselves: every step's saved state, and time travel by resuming from an older checkpoint.

python
from langchain.chat_models import init_chat_model
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import START, MessagesState, StateGraph

model = init_chat_model("anthropic:claude-opus-5-5")
graph = StateGraph(MessagesState)
graph.add_node("chat", lambda state: {"messages": [model.invoke(state["messages"])]})
graph.add_edge(START, "chat")
app = graph.compile(checkpointer=InMemorySaver())            # Step 1
config = {"configurable": {"thread_id": "asha"}}             # Step 2
app.invoke({"messages": [("user", "Hi, I'm Asha.")]}, config)
app.invoke({"messages": [("user", "What's my name?")]}, config)

history = list(app.get_state_history(config))                # Step 5: every snapshot, newest first
for snap in history:                                          # Step 3: one per step
    print(f"step {snap.metadata['step']:2}  next={snap.next}  messages={len(snap.values.get('messages', []))}")

# time travel: go back to the snapshot just before the second answer and run again from there
before = next(s for s in history if s.next == ("chat",))
replay = app.invoke(None, before.config)                      # a new branch from that point
print(f"replayed from step {before.metadata['step']}: new answer -> {replay['messages'][-1].content!r}")

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API.

What it printed
step  4  next=()  messages=4
step  3  next=('chat',)  messages=3
step  2  next=('__start__',)  messages=2
step  1  next=()  messages=2
step  0  next=('chat',)  messages=1
step -1  next=('__start__',)  messages=0
replayed from step 3: new answer -> 'You told me your name is Asha.'

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# A checkpointer saves a snapshot of the state after each step, per thread_id.
# Here it is SQLite from the standard library, like langgraph-checkpoint-sqlite without the details.
import json, sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE checkpoints (thread_id TEXT, step INTEGER, state TEXT)")

def save(thread_id, step, state):
    db.execute("INSERT INTO checkpoints VALUES (?, ?, ?)", (thread_id, step, json.dumps(state)))

def latest(thread_id):
    row = db.execute("SELECT step, state FROM checkpoints WHERE thread_id = ? "
                     "ORDER BY step DESC LIMIT 1", (thread_id,)).fetchone()
    return (row[0], json.loads(row[1])) if row else (0, {"messages": []})

def chatbot(state):
    n = sum(m.startswith("user") for m in state["messages"])
    return f"ai: that's message {n} from you"

# Step 1: compile(checkpointer=...) wires this in. Step 2: every call carries a thread_id
def invoke(message, config):
    thread_id = config["configurable"]["thread_id"]
    step, state = latest(thread_id)               # Step 4: load the latest snapshot for this thread
    for update in ("user: " + message, None):
        state["messages"].append(update or chatbot(state))
        step += 1
        save(thread_id, step, state)              # Step 3: snapshot after each step
    return state["messages"][-1]

alice = {"configurable": {"thread_id": "alice"}}
bob = {"configurable": {"thread_id": "bob"}}
print("alice:", invoke("hi", alice))
print("alice:", invoke("how are you?", alice))
print("bob:  ", invoke("hello", bob))
# Step 5: get_state_history - every snapshot, newest first
for step, state in db.execute("SELECT step, state FROM checkpoints WHERE thread_id = 'alice' ORDER BY step DESC"):
    print(f"alice step {step}: {json.loads(state)['messages']}")

✓ Ran with plain Python 3.9+.
