How does a multi-agent supervisor work?

In one lineA supervisor agent looks at the task and hands each piece to a specialist agent with its own tools and instructions, collecting results until the job is done.

↻ The supervisor keeps routing until the task is complete
Step by step
  1. The supervisor is an LLM whose tools are the other agents.
  2. It decides which specialist should handle the next part of the task.
  3. Each specialist runs its own loop with its own prompt and tools, and returns a result.
  4. The supervisor reviews the result and either routes again or produces the final answer.
Key details
  • Use it when tasks need clearly different skills or tools, or one agent's context would get too big.
  • Costs: more tokens, latency and failure points, and harder debugging.
  • Start with one agent and good tools; split only when evals show it helps.

Use it

What you'd write at work

The simplest multi-agent setup: specialists are agents, wrapped as tools of a supervisor agent.

python
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool

model = init_chat_model("anthropic:claude-opus-5-5")

@tool
def get_financials(quarter: str) -> str:
    """Revenue figures for a quarter."""
    return "Q3 revenue 4.2M (Q2: 3.75M)"

researcher = create_agent(model, [get_financials], system_prompt="You find numbers. Be precise.")
writer = create_agent(model, [], system_prompt="You write short, friendly team emails.")

@tool
def ask_researcher(question: str) -> str:
    """Ask the research agent for company numbers."""
    return researcher.invoke({"messages": [("user", question)]})["messages"][-1].content

@tool
def ask_writer(brief: str) -> str:
    """Ask the writing agent to draft text from a brief."""
    return writer.invoke({"messages": [("user", brief)]})["messages"][-1].content

supervisor = create_agent(model, [ask_researcher, ask_writer],
                          system_prompt="Coordinate the specialists to complete the task, then reply.")
result = supervisor.invoke({"messages": [("user", "Email the team a summary of Q3 revenue")]})
for m in result["messages"]:
    print(f"{m.type:5}", m.tool_calls[0]["name"] if getattr(m, "tool_calls", None) else m.content)

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

Under the hood

What the library does for you, with its real classes

A supervisor as an explicit LangGraph graph: a router node picks the next specialist with structured output and hands over control with Command(goto=...).

python
from typing import Literal

from pydantic import BaseModel
from langchain.chat_models import init_chat_model
from langchain.messages import AIMessage, HumanMessage, SystemMessage
from langgraph.graph import END, START, MessagesState, StateGraph
from langgraph.types import Command

model = init_chat_model("anthropic:claude-opus-5-5")

class Route(BaseModel):
    next: Literal["researcher", "writer", "FINISH"]
    instruction: str

router = model.with_structured_output(Route)

def supervisor(state: MessagesState) -> Command[Literal["researcher", "writer", "__end__"]]:
    # Step 2: decide which specialist acts next
    decision = router.invoke([SystemMessage("Route the task to researcher or writer, or FINISH.")] + state["messages"])
    print(f"supervisor -> {decision.next}" + (f": {decision.instruction}" if decision.instruction else ""))
    if decision.next == "FINISH":
        return Command(goto=END)                                      # Step 4
    return Command(goto=decision.next, update={"messages": [HumanMessage(decision.instruction, name="supervisor")]})

def specialist(name, prompt):
    def node(state: MessagesState) -> Command[Literal["supervisor"]]:
        reply = model.invoke([SystemMessage(prompt)] + state["messages"])   # Step 3: its own prompt (and tools)
        print(f"  {name}: {reply.content}")
        return Command(goto="supervisor", update={"messages": [AIMessage(reply.content, name=name)]})
    return node

graph = StateGraph(MessagesState)
graph.add_node("supervisor", supervisor)
graph.add_node("researcher", specialist("researcher", "You find numbers."))
graph.add_node("writer", specialist("writer", "You write short emails."))
graph.add_edge(START, "supervisor")
app = graph.compile()
app.invoke({"messages": [("user", "Email the team a summary of Q3 revenue")]})

✓ Ran with langchain 1.5.2, langgraph 1.2.24 · with a scripted chat model in place of the API.

What it printed

  researcher: Q3 revenue was 4.2M, up 12% on Q2.
supervisor -> writer: Write a two-line team email with those numbers.
  writer: Team - Q3 revenue reached 4.2M, up 12%. Great work!
supervisor -> FINISH

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# A supervisor is an LLM whose "tools" are other agents. Everything is stubbed so the routing is visible.
def research_agent(task):
    return "Q3 revenue was 4.2M, up 12% on Q2."
def writer_agent(task):
    return "Draft: 'Team - Q3 revenue reached 4.2M (+12%). Great work!'"
AGENTS = {"researcher": research_agent, "writer": writer_agent}

def supervisor_llm(task, results):
    # Step 1-2: decide which specialist should act next (a real supervisor asks an LLM this,
    # usually with structured output like {"next": "writer", "instruction": "..."})
    if "researcher" not in results:
        return "researcher", "find the Q3 revenue numbers"
    if "writer" not in results:
        return "writer", "write a short team email using: " + results["researcher"]
    return "FINISH", results["writer"]

task = "Email the team a summary of Q3 revenue"
results = {}
for turn in range(1, 6):
    choice, instruction = supervisor_llm(task, results)
    if choice == "FINISH":
        # Step 4: the supervisor is satisfied and returns the final answer
        print(f"turn {turn}: supervisor -> FINISH\nfinal: {instruction}")
        break
    print(f"turn {turn}: supervisor -> {choice}: {instruction!r}")
    # Step 3: the specialist runs its own loop (own prompt, own tools) and reports back
    results[choice] = AGENTS[choice](instruction)
    print(f"        {choice} reports: {results[choice]}")

✓ Ran with plain Python 3.9+.

What it prints
turn 1: supervisor -> researcher: 'find the Q3 revenue numbers'
        researcher reports: Q3 revenue was 4.2M, up 12% on Q2.
turn 2: supervisor -> writer: 'write a short team email using: Q3 revenue was 4.2M, up 12% on Q2.'
        writer reports: Draft: 'Team - Q3 revenue reached 4.2M (+12%). Great work!'
turn 3: supervisor -> FINISH
final: Draft: 'Team - Q3 revenue reached 4.2M (+12%). Great work!'
Watch it in a real system
  • LangGraph: graph.stream(inputs, stream_mode="updates", subgraphs=True) prints which agent (node or subgraph) ran at each step and what it returned.
  • Draw the graph: print(graph.get_graph().draw_mermaid()), then paste it into any Mermaid viewer.
  • In LangSmith, each specialist appears as its own branch of the trace, so you can see every routing decision and its cost.
