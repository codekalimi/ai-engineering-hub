How does LangGraph execute a graph?

In one lineIt runs in steps: the active nodes read the state and return updates, reducers merge the updates, a checkpoint is saved, and edges decide which nodes run next, until END.

Step by step
  1. The input becomes the initial state, which has the schema you defined (e.g. MessagesState).
  2. The nodes scheduled for this step run (in parallel if there are several). Each reads the state and returns only the keys it changes.
  3. Reducers merge the updates into the state, e.g. add_messages appends instead of overwriting.
  4. If a checkpointer is attached, the new state is saved for this thread.
  5. Edges decide the next nodes: fixed edges always go to the same node; conditional edges call a function that looks at the state.
  6. This repeats until END is reached or the recursion limit is hit.
Key details
  • This step-based model (inspired by Pregel) is what makes checkpoints, interrupts and time travel possible.
  • The default recursion limit stops runaway loops; raise it deliberately when needed.
