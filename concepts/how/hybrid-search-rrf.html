How does hybrid search with reciprocal rank fusion (RRF) work?

In one lineKeyword search and vector search run separately, and their two ranked lists are merged by rewarding documents that rank highly in either one.

Step by step
  1. BM25 scores documents by matching terms, giving rare terms more weight and normalizing for document length.
  2. Vector search scores documents by semantic similarity.
  3. The two kinds of score can't be compared, so RRF ignores scores and uses ranks: each document gets 1 / (k + rank) from each list, with k usually 60.
  4. Documents found by both lists, or ranked near the top of either, rise to the top.
Key details
  • Hybrid search fixes the classic embedding weakness: product codes, names, error IDs.
  • Some databases support hybrid search natively; otherwise run both searches and fuse in code.
  • Weighted fusion of normalized scores is an alternative to RRF.

Use it

What you'd write at work

Keyword search (BM25) and vector search, fused with reciprocal rank fusion. Search engines like Elasticsearch, OpenSearch, Weaviate and Qdrant offer the same as one query.

python
from langchain.embeddings import init_embeddings
from langchain_classic.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever
from langchain_core.vectorstores import InMemoryVectorStore

texts = ["Reset your password from the account settings page.",
         "Error code E-4021 means the payment token expired.",
         "How to change login credentials and recover access.",
         "Payment failed because the card was declined."]

keyword = BM25Retriever.from_texts(texts, k=3)
vector = InMemoryVectorStore.from_texts(texts, init_embeddings("openai:text-embedding-3-small")).as_retriever(search_kwargs={"k": 3})
hybrid = EnsembleRetriever(retrievers=[keyword, vector], weights=[0.5, 0.5])

for doc in hybrid.invoke("login problems after error E-4021"):
    print(doc.page_content)

✓ Ran with langchain 1.5.2, langchain-classic 1.1.0, langchain-community 0.4.2, langchain-core 1.8.4 · with a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

Under the hood

What the library does for you, with its real classes

What EnsembleRetriever does: run each retriever, then weighted RRF on the ranks (weight / (rank + 60)). Computed by hand and compared.

python
from langchain.embeddings import init_embeddings
from langchain_classic.retrievers import EnsembleRetriever
from langchain_community.retrievers import BM25Retriever
from langchain_core.vectorstores import InMemoryVectorStore

texts = ["Reset your password from the account settings page.",
         "Error code E-4021 means the payment token expired.",
         "How to change login credentials and recover access.",
         "Payment failed because the card was declined."]
query = "login problems after error E-4021"
keyword = BM25Retriever.from_texts(texts, k=3)
vector = InMemoryVectorStore.from_texts(texts, init_embeddings("openai:text-embedding-3-small")).as_retriever(search_kwargs={"k": 3})

rankings = [keyword.invoke(query), vector.invoke(query)]      # Steps 1-2: two separate rankings
for name, docs in zip(["BM25", "vector"], rankings):
    print(f"{name:6}:", [texts.index(d.page_content) for d in docs])

scores = {}                                                    # Step 3: RRF on ranks, not scores
for weight, docs in zip([0.5, 0.5], rankings):
    for rank, d in enumerate(docs, start=1):
        scores[d.page_content] = scores.get(d.page_content, 0) + weight / (rank + 60)
by_hand = sorted(scores, key=scores.get, reverse=True)
library = [d.page_content for d in EnsembleRetriever(retrievers=[keyword, vector], weights=[0.5, 0.5]).invoke(query)]
print("fused:", [texts.index(t) for t in by_hand], "| same as EnsembleRetriever:", by_hand == library)

✓ Ran with langchain 1.5.2, langchain-classic 1.1.0, langchain-community 0.4.2, langchain-core 1.8.4 · with a local embedding model (all-MiniLM-L6-v2) in place of the embedding API.

What it printed
BM25  : [2, 1, 3]
vector: [1, 2, 0]
fused: [2, 1, 3, 0] | same as EnsembleRetriever: True

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import math, re

docs = {
    "d1": "reset your password from the account settings page",
    "d2": "error code E-4021 means the payment token expired",
    "d3": "how to change login credentials and recover access",
    "d4": "payment failed because the card was declined",
}
tok = lambda t: re.findall(r"[a-z0-9-]+", t.lower())

# Step 1: BM25 - matching terms; rare terms weigh more; long documents are normalized
def bm25(query, k1=1.5, b=0.75):
    N = len(docs)
    avg = sum(len(tok(t)) for t in docs.values()) / N
    scores = {}
    for doc_id, text in docs.items():
        words, s = tok(text), 0.0
        for term in tok(query):
            df = sum(term in tok(t) for t in docs.values())
            if df == 0:
                continue
            idf = math.log(1 + (N - df + 0.5) / (df + 0.5))
            tf = words.count(term)
            s += idf * tf * (k1 + 1) / (tf + k1 * (1 - b + b * len(words) / avg))
        scores[doc_id] = s
    return [d for d in sorted(scores, key=scores.get, reverse=True) if scores[d] > 0]

# Step 2: vector search - pretend an embedding model returned this ranking
# (it understands "sign in problems" ~ password/credentials, but not the exact error code)
query = "sign in problems after E-4021"
vector_ranking = ["d3", "d1", "d4", "d2"]

# Step 3: RRF ignores the scores and combines ranks: 1 / (k + rank)
def rrf(*rankings, k=60):
    fused = {}
    for ranking in rankings:
        for rank, d in enumerate(ranking, start=1):
            fused[d] = fused.get(d, 0) + 1 / (k + rank)
    return sorted(fused.items(), key=lambda x: -x[1])

keyword_ranking = bm25(query)
print("BM25 ranking:  ", keyword_ranking)
print("vector ranking:", vector_ranking)
# Step 4: documents found by both, or near the top of either, rise
for d, s in rrf(keyword_ranking, vector_ranking):
    print(f"  {d} {s:.4f}  {docs[d]}")

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • LangChain: combine a BM25Retriever and a vector-store retriever in an EnsembleRetriever(retrievers=[bm25, vector], weights=[0.5, 0.5]), which fuses with RRF.
  • Elasticsearch/OpenSearch, Weaviate, Qdrant and pgvector setups all offer hybrid queries; log both ranked lists before fusion to see what each one contributes.
  • Test with an exact code or ID (like an error code): keyword search finds it, embeddings often don’t.
