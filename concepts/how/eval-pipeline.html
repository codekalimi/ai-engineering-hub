How does an LLM evaluation pipeline work?

In one lineA fixed dataset is run through the new version of the app, each output is scored by code checks and an LLM judge, and the scores are compared with the current version before deploying.

Step by step
  1. Build a dataset from real usage and edge cases, with expected answers or grading criteria.
  2. Run every case through the new version (new prompt, model or retrieval settings).
  3. Score outputs: exact or programmatic checks where possible, an LLM judge with a rubric for fuzzier qualities.
  4. Compare case by case with the current version's scores.
  5. Block the release if important cases regress; otherwise deploy and monitor.
Key details
  • Run it in CI on every prompt or model change.
  • Keep adding production failures to the dataset so they can't come back.
  • Track cost and latency alongside quality.

Use it

What you'd write at work

Run your app over a stored dataset with evaluators, as an experiment you can compare with the last one. LangSmith shown; Braintrust, promptfoo and others work the same way.

python
from langsmith import Client

client = Client()

def target(inputs: dict) -> dict:              # your app, called once per dataset example
    return {"answer": my_app(inputs["question"])}

def correct(outputs: dict, reference_outputs: dict) -> bool:    # a programmatic evaluator
    return reference_outputs["answer"].lower() in outputs["answer"].lower()

results = client.evaluate(
    target,
    data="support-bot-golden",                 # Step 1: a dataset built from real traffic
    evaluators=[correct],                      # Step 3: checks (and LLM judges)
    experiment_prefix="prompt-v2",             # Step 4: compare with the previous experiment in the UI
)

Checked, not run: needs a LangSmith account and API key; syntax and imports were checked.

Under the hood

What the library does for you, with its real classes

What evaluate() does, minus the UI: run each case, score it, compare case by case with the stored baseline, and fail the build on regressions (exit code for CI).

python
import json
import sys

dataset = [  # Step 1
    {"id": "math-1", "question": "What is 15% of 200?", "expect": "30"},
    {"id": "json-1", "question": "Return JSON with key ok", "expect": '{"ok"'},
    {"id": "refund-1", "question": "Refund window?", "expect": "30 days"},
    {"id": "fr-1", "question": "Say hello in French", "expect": "bonjour"},
]
def app_v2(q):     # the candidate version (stands in for your chain or agent)
    return {"What is 15% of 200?": "The answer is 30.", "Return JSON with key ok": 'Sure! {"ok": true}',
            "Refund window?": "You have 30 days.", "Say hello in French": "Bonjour"}[q]

baseline = {"math-1": True, "json-1": True, "refund-1": True, "fr-1": False}   # last release's results

results = {}
for case in dataset:                                           # Steps 2-3: run and score
    output = app_v2(case["question"])
    results[case["id"]] = case["expect"].lower() in output.lower() and not output.startswith("Sure!")
print(json.dumps(results))

regressions = [k for k, ok in results.items() if baseline[k] and not ok]    # Step 4: case by case
fixed = [k for k, ok in results.items() if ok and not baseline[k]]
print(f"pass rate {sum(results.values())}/{len(results)} (baseline {sum(baseline.values())}/{len(baseline)})")
print("fixed:", fixed, "| regressions:", regressions)
exit_code = 1 if regressions else 0                            # Step 5: CI blocks the release
print("exit code", exit_code)
sys.exit(0)   # (the real script would sys.exit(exit_code))

✓ Ran with Python 3.12.14.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Step 1: a dataset of real cases, each with a check
dataset = [
    {"q": "What is 15% of 200?", "check": lambda a: "30" in a},
    {"q": "Return JSON with key ok", "check": lambda a: a.strip().startswith("{") and '"ok"' in a},
    {"q": "Refund window?", "check": lambda a: "30 days" in a},
    {"q": "Say hello in French", "check": lambda a: "bonjour" in a.lower()},
]
def app_v1(q):   # the current version
    return {"What is 15% of 200?": "30", "Return JSON with key ok": '{"ok": true}',
            "Refund window?": "30 days", "Say hello in French": "Hello"}[q]
def app_v2(q):   # the candidate: a new prompt that fixes French but breaks JSON
    return {"What is 15% of 200?": "The answer is 30.", "Return JSON with key ok": 'Sure! {"ok": true}',
            "Refund window?": "You have 30 days.", "Say hello in French": "Bonjour"}[q]

# Step 2-3: run every case through both versions and score them
results = [(c["q"], c["check"](app_v1(c["q"])), c["check"](app_v2(c["q"]))) for c in dataset]
# Step 4: compare case by case, not just the average
for q, old, new in results:
    note = "REGRESSION" if old and not new else ("fixed" if new and not old else "")
    print(f"{q:26} v1={'pass' if old else 'FAIL'}  v2={'pass' if new else 'FAIL'}  {note}")
print(f"pass rate: v1 {sum(r[1] for r in results)}/4, v2 {sum(r[2] for r in results)}/4")
# Step 5: same average, but v2 broke a case that used to pass
if any(old and not new for _, old, new in results):
    print("release blocked: fix the regression first")

✓ Ran with plain Python 3.9+.
