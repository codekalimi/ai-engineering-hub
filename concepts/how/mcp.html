How does MCP (Model Context Protocol) work?

In one lineMCP standardizes how AI apps discover and call tools and data: an MCP server describes its tools, and any MCP client can list and call them.

Step by step
  1. The host app (an IDE assistant, a chat app, your agent) runs an MCP client for each server it connects to.
  2. On connect, client and server exchange capabilities, and the client lists the server's tools.
  3. The tool descriptions are handed to the LLM like any other tool schemas.
  4. When the LLM picks a tool, the client sends tools/call to the server.
  5. The server runs the real work (API, database, files) and returns the result.
Key details
  • Servers can also expose resources (readable data) and prompts (templates).
  • Transports: stdio for local servers, HTTP for remote ones, with OAuth for authentication.
  • Treat third-party servers as untrusted code: they can inject instructions or exfiltrate data.

Use it

What you'd write at work

Connect to an MCP server, get its tools as LangChain tools, hand them to an agent. The server is the 10-line FastMCP program shown in Level 2.

python
import asyncio
import sys
from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain_mcp_adapters.client import MultiServerMCPClient

async def main():
    client = MultiServerMCPClient({
        "helpdesk": {"transport": "stdio", "command": sys.executable, "args": ["server.py"]},
    })
    tools = await client.get_tools()                      # MCP tools -> LangChain tools
    print("tools from the server:", [t.name for t in tools])
    agent = create_agent(init_chat_model("anthropic:claude-opus-5-5"), tools)
    result = await agent.ainvoke({"messages": [("user", "What's the status of ticket T-7?")]})
    print(result["messages"][-1].content)

asyncio.run(main())

✓ Ran with langchain 1.5.2, langchain-mcp-adapters 0.3.2 · with a scripted chat model in place of the API.

What it printed
tools from the server: ['get_ticket']
Ticket T-7: the printer on floor 3 is offline, and the ticket is still open.

Under the hood

What the library does for you, with its real classes

Both halves with the official MCP Python SDK (1.x, the version langchain-mcp-adapters supports): a FastMCP server, and a client session doing the handshake, tools/list and tools/call from the diagram. In SDK 2.x, FastMCP is renamed MCPServer (from mcp.server.mcpserver import MCPServer).

python
import asyncio
import sys
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

SERVER = '''
from mcp.server.fastmcp import FastMCP
server = FastMCP("helpdesk")

@server.tool()
def get_ticket(id: str) -> str:
    """Look up a support ticket by id."""
    return {"T-7": "Printer on floor 3 is offline (open)"}.get(id, "not found")

server.run()   # stdio transport: JSON-RPC messages on stdin/stdout
'''
open("server.py", "w").write(SERVER)

async def main():
    params = StdioServerParameters(command=sys.executable, args=["server.py"])   # Step 1: start the server
    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            info = await session.initialize()                                     # Step 2: handshake
            print("connected to:", info.serverInfo.name, "| protocol", info.protocolVersion)
            listed = await session.list_tools()                                   # tools/list
            for t in listed.tools:
                print("tool:", t.name, "-", t.description)                        # Step 3: goes to the LLM
            result = await session.call_tool("get_ticket", {"id": "T-7"})         # Step 4: tools/call
            print("result:", result.content[0].text)                              # Step 5

asyncio.run(main())

✓ Ran with mcp 1.30.0.

What it printed
connected to: helpdesk | protocol 2025-11-25
tool: get_ticket - Look up a support ticket by id.
result: Printer on floor 3 is offline (open)

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# MCP = JSON-RPC 2.0 messages between a client (inside the host app) and a server (a separate
# program, over stdio or HTTP). Here the server is a function so you can read every message.
import json

TOOLS = [{"name": "get_ticket", "description": "Look up a support ticket by id",
          "inputSchema": {"type": "object", "properties": {"id": {"type": "string"}}, "required": ["id"]}}]
TICKETS = {"T-7": "Printer on floor 3 is offline (open)"}

def server(raw):
    msg = json.loads(raw)
    if msg["method"] == "initialize":
        result = {"protocolVersion": "2025-06-18", "capabilities": {"tools": {}}, "serverInfo": {"name": "helpdesk"}}
    elif msg["method"] == "tools/list":
        result = {"tools": TOOLS}
    elif msg["method"] == "tools/call":
        # Step 5: the server does the real work (API, database, files)
        ticket = TICKETS.get(msg["params"]["arguments"]["id"], "not found")
        result = {"content": [{"type": "text", "text": ticket}]}
    return json.dumps({"jsonrpc": "2.0", "id": msg["id"], "result": result})

next_id = 0
def send(method, params=None):
    global next_id
    next_id += 1
    raw = json.dumps({"jsonrpc": "2.0", "id": next_id, "method": method, "params": params or {}})
    print("client ->", raw[:105])
    result = json.loads(server(raw))["result"]
    print("server <-", json.dumps(result)[:105])
    return result

# Step 1-2: the host's client connects, exchanges capabilities, lists the tools
send("initialize", {"protocolVersion": "2025-06-18", "capabilities": {}, "clientInfo": {"name": "my-agent"}})
tools = send("tools/list")["tools"]
# Step 3: these schemas go to the LLM like any other tools; say it picks get_ticket
# Step 4: the client sends tools/call
result = send("tools/call", {"name": "get_ticket", "arguments": {"id": "T-7"}})
print("text handed back to the LLM:", result["content"][0]["text"])

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • MCP Inspector: npx @modelcontextprotocol/inspector <command that starts your server> opens a UI where you can call initialize, tools/list and tools/call yourself and read the raw JSON-RPC messages.
  • A stdio server is just a process reading JSON lines on stdin and writing them on stdout; log them to stderr to watch the conversation.
  • In your host app’s logs (Claude Desktop, IDE assistants and others write MCP logs), look for the tools/list response to see exactly which tool descriptions the model receives.
