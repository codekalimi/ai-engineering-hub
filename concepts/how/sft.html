How does supervised fine-tuning (SFT) work?

In one lineThe model is trained on example prompt → ideal-answer pairs: it predicts the answer tokens, the error is measured, and the weights are nudged to make the ideal answer more likely.

Step by step
  1. Collect hundreds to thousands of high-quality examples of the behaviour you want.
  2. Format each one with the model's chat template (system, user, assistant turns).
  3. The model reads the prompt and predicts the answer token by token.
  4. The loss measures how far its predictions are from the ideal answer, counting only the answer tokens.
  5. Backpropagation adjusts the weights (or LoRA adapters) slightly to reduce the loss.
  6. After training, evaluate on examples it hasn't seen, to check it improved and didn't regress elsewhere.
Key details
  • Data quality matters far more than quantity.
  • Too many epochs leads to overfitting: great on training data, worse on new inputs.
  • Fine-tuning teaches behaviour and format; use RAG for facts that change.

Use it

What you'd write at work

Supervised fine-tuning with TRL and LoRA, on a list of conversations. Real run: 3 steps on a 0.5B model on CPU (a real job runs thousands of steps on a GPU).

python
from datasets import Dataset
from peft import LoraConfig
from trl import SFTConfig, SFTTrainer

examples = [  # Step 1: examples of exactly the behaviour you want
    {"messages": [{"role": "user", "content": "Refund status for order 123?"},
                  {"role": "assistant", "content": "Order 123: refund issued on 2 May, arrives in 5 days."}]},
    {"messages": [{"role": "user", "content": "Refund status for order 456?"},
                  {"role": "assistant", "content": "Order 456: refund pending approval."}]},
] * 4

trainer = SFTTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    train_dataset=Dataset.from_list(examples),        # Step 2: chat template applied for you
    peft_config=LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"]),
    args=SFTConfig(output_dir="sft-out", max_steps=3, per_device_train_batch_size=2, learning_rate=2e-4,
                   logging_steps=1, report_to=[], save_strategy="no", use_cpu=True),
)
result = trainer.train()                              # Steps 3-5: forward, loss on answers, update
print(f"trained {result.global_step} steps, final loss {result.training_loss:.3f}")

✓ Ran with datasets 5.2.0, peft 0.22.0, trl 1.18.2.

Under the hood

What the library does for you, with its real classes

What the trainer's data collator does: apply the chat template, then mask everything except the assistant's answer with -100 so only the answer is learned.

python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name).eval()
messages = [{"role": "user", "content": "Refund status for order 123?"},
            {"role": "assistant", "content": "Refund issued, arrives in 5 days."}]

prompt = tok.apply_chat_template(messages[:1], add_generation_prompt=True, tokenize=False)   # Step 2
full = tok.apply_chat_template(messages, tokenize=False)
print("training text:", repr(full[-90:]))
ids = tok(full, return_tensors="pt").input_ids
n_prompt = len(tok(prompt).input_ids)
labels = ids.clone()
labels[:, :n_prompt] = -100                                        # Step 4: ignore prompt positions
print(f"{ids.shape[1]} tokens, {int((labels != -100).sum())} of them count for the loss:",
      repr(tok.decode(ids[0, n_prompt:])))

with torch.no_grad():
    answer_only = model(ids, labels=labels).loss                    # what SFT optimizes
    everything = model(ids, labels=ids).loss                        # pretraining-style, for contrast
print(f"loss on the answer only {answer_only:.3f} vs on all tokens {everything:.3f}")

✓ Ran with torch 2.15.0, transformers 5.24.0.

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
import math

# Step 1: one example of the behaviour we want (real runs use hundreds to thousands)
example = [{"role": "user", "content": "Capital of France?"}, {"role": "assistant", "content": "Paris."}]

# Step 2: format with the chat template (each model family has its own special tokens)
def chat_template(messages):
    return "".join(f"<|{m['role']}|>{m['content']}<|end|>" for m in messages)
print("training text:", chat_template(example))

# Step 4 (setup): only the ANSWER tokens count - prompt positions get label -100 (ignored)
tokens = ["<|user|>", "Capital", "of", "France?", "<|end|>", "<|assistant|>", "Paris.", "<|end|>"]
answer_start = tokens.index("<|assistant|>") + 1
labels = [tok if i >= answer_start else -100 for i, tok in enumerate(tokens)]
print("labels:", labels)

# Step 3-5: predict the answer token, measure the loss, nudge the weights; repeat
scores = {"Paris.": 0.0, "Lyon.": 0.0, "London.": 0.0}     # the model's scores for the next token
for epoch in range(1, 6):
    z = sum(math.exp(s) for s in scores.values())
    p = {t: math.exp(s) / z for t, s in scores.items()}
    loss = -math.log(p["Paris."])                          # cross-entropy on the correct token
    for t in scores:                                       # gradient step, learning rate 1.0
        scores[t] -= p[t] - (1.0 if t == "Paris." else 0.0)
    print(f"epoch {epoch}: P('Paris.') = {p['Paris.']:.2f}, loss = {loss:.2f}")
# Step 6: evaluate on examples the model has not seen

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • Print tokenizer.apply_chat_template(messages, tokenize=False) for one training example: that string, special tokens included, is what the model is trained on.
  • TRL SFTTrainer: look at a collated batch and check that the prompt positions in labels are -100, so only the answer is learned.
  • Watch training and evaluation loss together: training loss falling while evaluation loss rises means it is memorizing.
