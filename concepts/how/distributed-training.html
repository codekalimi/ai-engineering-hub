How does distributed training (data parallel, FSDP) work?

In one lineEach GPU trains on different data; gradients are averaged across GPUs every step. FSDP also splits the model's weights and optimizer state across GPUs so bigger models fit.

Step by step
  1. The training data is split so each GPU gets a different mini-batch.
  2. Each GPU runs the forward and backward pass to compute gradients.
  3. An all-reduce averages the gradients across all GPUs.
  4. Every GPU applies the same update, so all copies stay identical.
  5. With FSDP or ZeRO, parameters, gradients and optimizer states are sharded across GPUs and gathered layer by layer when needed.
Key details
  • Plain data parallelism (DDP) needs the whole model plus optimizer state on each GPU.
  • Checkpoint regularly: long multi-node jobs will hit hardware failures.

Use it

What you'd write at work

Data-parallel training with PyTorch DDP: wrap the model, give each process its own data shard. Real run with 2 CPU processes (gloo); on GPUs use torchrun and the nccl backend.

python
import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp
from torch.nn.parallel import DistributedDataParallel as DDP

def train(rank, world_size):
    os.environ.update(MASTER_ADDR="127.0.0.1", MASTER_PORT="29512")
    dist.init_process_group("gloo", rank=rank, world_size=world_size)     # "nccl" on GPUs
    torch.manual_seed(0)                                                  # same starting weights everywhere
    model = DDP(torch.nn.Linear(4, 1))
    opt = torch.optim.SGD(model.parameters(), lr=0.05)
    data = torch.randn(64, 4)
    target = data @ torch.tensor([[1.0], [2.0], [-1.0], [0.5]])
    shard = slice(rank * 32, (rank + 1) * 32)                             # each process: different examples
    for step in range(30):
        loss = ((model(data[shard]) - target[shard]) ** 2).mean()
        opt.zero_grad()
        loss.backward()                                                   # DDP all-reduces gradients here
        opt.step()
    w = model.module.weight.detach()
    print(f"rank {rank}: loss {loss.item():.4f}, weights {[round(v, 2) for v in w[0].tolist()]}")
    dist.destroy_process_group()

if __name__ == "__main__":
    mp.spawn(train, args=(2,), nprocs=2)

✓ Ran with torch 2.15.0.

Under the hood

What the library does for you, with its real classes

What DDP does inside backward(): all-reduce the gradients so every process applies the identical update. Done by hand with dist.all_reduce.

python
import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp

def train(rank, world_size):
    os.environ.update(MASTER_ADDR="127.0.0.1", MASTER_PORT="29513")
    dist.init_process_group("gloo", rank=rank, world_size=world_size)
    torch.manual_seed(0)
    model = torch.nn.Linear(4, 1)                                   # a plain model, no DDP wrapper
    data = torch.randn(64, 4)
    target = data @ torch.tensor([[1.0], [2.0], [-1.0], [0.5]])
    shard = slice(rank * 32, (rank + 1) * 32)                       # Step 1: different data per process
    loss = ((model(data[shard]) - target[shard]) ** 2).mean()
    loss.backward()                                                 # Step 2: local gradients
    local = model.weight.grad.clone()
    for p in model.parameters():
        dist.all_reduce(p.grad, op=dist.ReduceOp.SUM)               # Step 3: sum across processes...
        p.grad /= world_size                                        # ...then average
    print(f"rank {rank}: local grad {[round(g, 2) for g in local[0].tolist()]} -> averaged {[round(g, 2) for g in model.weight.grad[0].tolist()]}")
    dist.destroy_process_group()                                    # Step 4: identical grads -> identical update

if __name__ == "__main__":
    mp.spawn(train, args=(2,), nprocs=2)
# Step 5 (FSDP): torch.distributed.fsdp.fully_shard(model) also shards weights and optimizer state

✓ Ran with torch 2.15.0.

rank 0: local grad [-3.31, -3.03, 0.45, -1.65] -> averaged [-2.12, -2.98, 0.54, -1.56]

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Data-parallel training of y = w * x on 2 "GPUs", each with a full copy of w.
data = [(1, 2), (2, 4), (3, 6), (4, 8)]          # the true w is 2
shards = [data[:2], data[2:]]                    # Step 1: each GPU gets different examples
w = [0.0, 0.0]                                   # identical copies on GPU 0 and GPU 1
lr = 0.02

def grad(w_local, batch):                        # Step 2: forward + backward on the local batch
    return sum(2 * (w_local * x - y) * x for x, y in batch) / len(batch)

for step in range(1, 6):
    g = [grad(w[i], shards[i]) for i in range(2)]
    g_avg = sum(g) / 2                           # Step 3: all-reduce averages the gradients
    w = [wi - lr * g_avg for wi in w]            # Step 4: same update everywhere -> copies stay equal
    print(f"step {step}: local grads {[round(v, 1) for v in g]} -> average {g_avg:6.2f} -> w = {w[0]:.3f} on both GPUs")

# Step 5 (FSDP/ZeRO): each GPU keeps only a SHARD of weights, gradients and optimizer state,
# and all-gathers a layer's full weights just before using them.
P = 7e9
print(f"7B model, mixed-precision Adam (~16 bytes/weight): {P * 16 / 1e9:.0f} GB per full copy, "
      f"~{P * 16 / 8 / 1e9:.0f} GB per GPU with FSDP over 8 GPUs")

✓ Ran with plain Python 3.9+.

Watch it in a real system
  • Launch with torchrun --nproc_per_node=2 train.py: each process prints its RANK and sees a different slice of the data.
  • NCCL_DEBUG=INFO logs the all-reduce setup; PyTorch’s profiler shows how much time goes to communication vs compute.
  • Watch nvidia-smi per GPU: with plain data parallelism memory is the same on every GPU; with FSDP each holds roughly 1/N of the model state.
