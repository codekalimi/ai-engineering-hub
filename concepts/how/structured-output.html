How does structured output (JSON mode, constrained decoding) work?

In one lineEither the model is trained to emit schema-shaped JSON (as in tool calling), or the server restricts which tokens may be chosen at each step so the output must match your schema.

How to read this diagram

Flow diagram: read left to right. Dashed loops show steps that repeat; ↓ joins rows that follow on from each other.

↻ At every step, recompute which tokens keep the output valid
Step by step
  1. Your schema (often generated from a Pydantic class) is turned into a grammar that describes every valid output.
  2. At each generation step, the server works out which tokens could legally come next.
  3. All other tokens get their probability set to zero before sampling.
  4. The output is therefore guaranteed to parse and match the schema's structure.
Key details
  • Provider structured-output modes and tool calling build on this; LangChain's with_structured_output chooses the right mechanism.
  • Valid structure doesn't mean correct content. Still validate the values.
  • Open-source servers implement it with libraries such as Outlines or XGrammar.

Use it

What you'd write at work

Describe the shape you want as a Pydantic class; you get a validated object back, not text to parse.

python
from typing import Literal

from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model

class Ticket(BaseModel):
    category: Literal["billing", "technical", "other"]
    urgent: bool
    summary: str = Field(description="One sentence")

model = init_chat_model("anthropic:claude-opus-5-5")
extractor = model.with_structured_output(Ticket)
ticket = extractor.invoke("My card was charged twice and I need this fixed today!")
print(type(ticket).__name__, ticket.model_dump())

✓ Ran with langchain 1.5.2 · with a scripted chat model in place of the API.

What it printed
Ticket {'category': 'billing', 'urgent': True, 'summary': 'Customer was charged twice and needs a fix today.'}

Under the hood

What the library does for you, with its real classes

What with_structured_output does: your class becomes a JSON schema sent as a tool, the model's tool call is parsed and validated. With strict tools or structured-output mode the server also constrains the tokens (Steps 2-3).

python
import json
from typing import Literal

from pydantic import BaseModel, ValidationError
from langchain.chat_models import init_chat_model
from langchain_core.output_parsers.openai_tools import PydanticToolsParser
from langchain_core.utils.function_calling import convert_to_openai_tool

class Ticket(BaseModel):
    category: Literal["billing", "technical", "other"]
    urgent: bool
    summary: str

schema = convert_to_openai_tool(Ticket)["function"]["parameters"]     # Step 1: class -> JSON schema
print("schema sent:", json.dumps(schema))

model = init_chat_model("anthropic:claude-opus-5-5").bind_tools([Ticket])
ai = model.invoke("My card was charged twice and I need this fixed today!")
print("model returned a tool call:", ai.tool_calls[0]["args"])

ticket = PydanticToolsParser(tools=[Ticket], first_tool_only=True).invoke(ai)   # parse + validate
print("parsed:", repr(ticket))
try:
    Ticket(category="refund", urgent="maybe", summary="x")             # what validation catches
except ValidationError as err:
    print("rejected:", err.error_count(), "errors")

✓ Ran with langchain 1.5.2, langchain-core 1.8.4 · with a scripted chat model in place of the API.

What it printed
schema sent: {"properties": {"category": {"enum": ["billing", "technical", "other"], "type": "string"}, "urgent": {"type": "boolean"}, "summary": {"type": "string"}}, "required": ["category", "urgent", "summary"], "type": "object"}
model returned a tool call: {'category': 'billing', 'urgent': True, 'summary': 'Charged twice.'}
parsed: Ticket(category='billing', urgent=True, summary='Charged twice.')
rejected: 2 errors

From scratch

The idea in plain Python, no libraries

A tiny version of the mechanism. The Step comments match the numbered steps above. Save it as a .py file and run python3 file.py: nothing to install.

python3 · standard library only
# Constrained generation masks out every token the schema does not allow, before each pick.
import json, random
random.seed(0)

VOCAB = ['{', '}', '"sentiment"', ':', '"pos"', '"neg"', 'Sure!', 'Here', ',']
# Step 1: the schema {"sentiment": "pos" | "neg"} becomes a grammar: what may come at each position
GRAMMAR = [['{'], ['"sentiment"'], [':'], ['"pos"', '"neg"'], ['}']]

def model_scores(so_far):
    # the unconstrained model would love to chat first
    return {t: (5.0 if t in ('Sure!', 'Here') else random.uniform(0, 2)) for t in VOCAB}

out = []
while len(out) < len(GRAMMAR):
    # Step 2: work out which tokens could legally come next
    legal = GRAMMAR[len(out)]
    scores = model_scores(out)
    wanted = max(scores, key=scores.get)
    # Step 3: every other token gets probability zero (score -inf) before picking
    masked = {t: (s if t in legal else float("-inf")) for t, s in scores.items()}
    pick = max(masked, key=masked.get)
    print(f"model wanted {wanted:12} allowed {legal} -> {pick}")
    out.append(pick)

# Step 4: guaranteed to parse
text = "".join(out)
print("output:", text, "->", json.loads(text))

✓ Ran with plain Python 3.9+.

What it prints
model wanted Sure!        allowed ['{'] -> {
model wanted Sure!        allowed ['"sentiment"'] -> "sentiment"
model wanted Sure!        allowed [':'] -> :
model wanted Sure!        allowed ['"pos"', '"neg"'] -> "neg"
model wanted Sure!        allowed ['}'] -> }
output: {"sentiment":"neg"} -> {'sentiment': 'neg'}
